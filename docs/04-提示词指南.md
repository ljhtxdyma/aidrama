# 04 提示词与分镜写作指南

本文讲三件事：`project.yaml` 里的分镜字段怎么写；流水线怎么把这些字段编译成 MiniMax H3 和 Qwen-Image 的提示词；什么时候需要手改提示词，怎么改。

文中的提示词示例都是真实输出。做法是在云端用 `--mock` 跑内置示例《第七封信》第 1 集：

```bash
python -m aidrama init-demo /tmp/doc_demo
python -m aidrama run /tmp/doc_demo ep01 --mock --takes 1
# 结果在 /tmp/doc_demo/episodes/ep01/prompts/*.txt，图像提示词在 /tmp/doc_demo/graphs/*.json
```

`--mock` 模式不加载模型，LLM 扩写这一步会原样返回确定性草稿。所以下面看到的是“编译器输出”，不是本地 LLM 扩写后的版本。H3 拿到这些提示词后实际生成的画面和口型，云端没有 GPU，没有验证（未确认）。

相关文档：流程和命令见 [docs/03-工作流SOP.md](03-工作流SOP.md)，质检与重抽见 [docs/05-质检与返工.md](05-质检与返工.md)，AI 标识和角色原创要求见 [docs/07-合规与授权.md](07-合规与授权.md)，原始调研见 [docs/research/10-剧本分镜与自动化框架.md](research/10-剧本分镜与自动化框架.md)。

## 1. 提示词在流水线里的位置

原则：**你主要改 `project.yaml`，H3 提示词由代码生成。** 只有个别段需要手改时，才写 `.manual.txt`。

| 阶段（命令） | 谁来写提示词 | 用到的字段 / 模板 | 产物 |
|---|---|---|---|
| `new` | 本地 LLM，系统提示词 `aidrama/prompts/bible_system.md` | 一句话创意 | `project.yaml` 的 series / characters / locations / episodes |
| `storyboard` | 本地 LLM，`aidrama/prompts/storyboard_system.md` | 剧集圣经摘要 + 本集梗概 + `--notes` | `episodes[].scenes[].shots[]` |
| `cast` | 代码模板（`aidrama/pipeline.py`） | appearance_en、outfits、description_en、image_style_en | `assets/characters/<id>/front.png`、`sheet_<服装>.png`、`voice.wav`；`assets/locations/<id>/plate.png` |
| `voice` | 不用提示词 | dialogue 的 text、emotion、emo_vector | `episodes/<ep>/audio/<镜头>_l<n>.wav` |
| `plan` | 不用提示词 | duration、配音实际时长、transition、method | `episodes[].segments[]`（每段的切点时间） |
| `keyframes` | 代码模板 | keyframe_prompt、shot_size、angle、lighting_en | `episodes/<ep>/keyframes/<镜头>.png` |
| `video` | `aidrama/h3prompt.py` 编译 → lint → 本地 LLM 扩写（可关） | 分镜和角色的全部英文字段 | `episodes/<ep>/prompts/<段>.draft.txt`、`<段>.txt`；有 `<段>.manual.txt` 时优先用它 |
| `music` | 不用改写 | bgm_prompt | `episodes/<ep>/audio/bgm.*` |

每次实际提交给 ComfyUI 的工作流都会存进 `<工程>/graphs/<名字>.json`，图像提示词原文就在里面。审片页 `review.html` 的每段下面也能展开看到 H3 提示词。

改完字段后要重跑哪些步骤：

| 改了什么 | 需要重跑 |
|---|---|
| keyframe_prompt / angle / shot_size | `keyframes <工程> ep01 --only s01_02 --force`，然后 `video <工程> ep01 --only s01_02 --force` |
| motion_prompt / camera_en / sfx / delivery / end_state | `video ... --only <镜头或段> --force`（每次 video 都会重新编译这段的提示词） |
| 台词 text、emotion | 先删掉这句台词的 `audio:` 和 `duration:`（或 `voice --force` 全部重配）→ `voice` → `plan` → `video --only ... --force` |
| duration、增删镜头、transition、method | `plan`（段号可能变，见第 5 节）→ 新镜头跑 `keyframes` → `video` |
| 角色外貌、服装 | 删掉该角色 `refs` 里的 `front` / `sheet_*` → `cast` → 相关镜头 `keyframes --force` → `video --force` |
| 音色描述 voice.description | 删掉 `voice.ref_audio` → `cast` → `voice --force` |

`--only` 可以写段号（`ep01_g02`），也可以写镜头号（`s01_04`），多个用逗号隔开。改完 yaml 先跑一次 `python -m aidrama check <工程>`。

## 2. project.yaml 字段说明

### 2.1 语言约定

- **中文字段**（给人看、给 TTS 用）：`name`、`appearance`、`personality`、`voice.description`、`voice.design_text`、`action`、`summary`、`dialogue[].text`。
- **英文字段**（直接进提示词）：其余所有 `*_en`，以及 `outfits`、`keyframe_prompt`、`end_keyframe_prompt`、`motion_prompt`、`end_state`、`sfx`、`camera_en`、`delivery`、`bgm_prompt`。进入 H3 提示词的英文字段里如果出现两个以上连续汉字，lint 会报错（台词和英文双引号里的画面文字除外）。
- **`[角色id]` 占位符**只能写在 `keyframe_prompt`、`end_keyframe_prompt`、`motion_prompt`、`end_state` 四个字段里。编排器按模式替换：H3 Ref2VA 换成 `<Subject N>`；H3 FL2VA 换成英文身份短语（段里第一个角色带服装）；关键帧换成 `the woman from Picture N`。`camera_en`、`sfx`、`lighting_en` 里的 `[角色id]` 不会被替换，会被 lint 拦下。
- YAML 里以 `[` 开头的值必须加引号：`motion_prompt: '[lin_wan] reads the address ...'`。不加引号会被当成列表，读取报错。

### 2.2 series

| 字段 | 说明 |
|---|---|
| `style_en` | H3 风格开头，默认 `Live-action, cinematic`。FL2VA 放在 `[Shot 1]` 后，Ref2VA 编成 `The target video is in a live-action, cinematic style`。 |
| `image_style_en` | 所有图像提示词末尾统一追加的画风短语。 |
| `language` | 台词语言，`zh` 对应 `<d>[Chinese] …</d>`（另有 yue / en / ja / ko）。 |
| `episode_seconds` | 单集目标时长，分镜 LLM 按它控制总长（允许偏差见 storyboard_system.md）。 |
| `ai_label` | 成片右上角的显式 AI 标识文字，默认 `本内容由AI生成`。 |

### 2.3 characters

| 字段 | 写法 |
|---|---|
| `id` | 小写英文加下划线，如 `lin_wan`。 |
| `gender` | 决定关键帧里叫 `the woman` 还是 `the man`；留空就写成 `the person`。 |
| `identity_en` | 一眼可见的外观，10~20 个词，小写 `a` 开头，不写服装。例：`a slender woman in her mid-20s with a low black ponytail`。每条 H3 提示词都会用到。 |
| `appearance_en` | 定妆照用的详细五官，40~80 个词，不写服装。只用在 `front.png` 这一步。 |
| `outfits` | 服装 key → 英文“连续性锁”短语（颜色 + 材质 + 款式 + 配饰），以 `a/an` 开头，不要写 `wearing`（代码会加）。 |
| `voice.description` | 中文音色设计指令，交给 Qwen3-TTS VoiceDesign。 |
| `voice.voice_en` | 英文音色短语，说话人在本段第一次开口时写进 H3 提示词。 |
| `voice.design_text` | 试音台词，40~60 字，用来生成 10~15 秒的参考音色。 |
| `voice.emotion_refs` | 可选：`{情绪标签: 情绪参考音频}`。有对应标签时用参考音频控制情绪（emo_alpha 0.8），不再用向量。 |
| `refs` | 自动生成：`front`、`sheet_<服装key>`。 |

### 2.4 locations / scenes

- `locations[].description_en`：空场景描述，30~60 个词，写布局、陈设、材质、色调、光线，不写人。用于生成 `plate.png`；关键帧放不下场景图时，这段文字会直接写进关键帧提示词。
- `scenes[].lighting_en`：本场统一光线，写成小写开头、不带句号的短语，例如 `low-key light from a green banker's lamp with cool blue moonlight from a high window`。它会被嵌进句子中间。
- `scenes[].sound_en`：本场环境声底，写完整英文句子，进入 `overall_soundscape`。留空时用默认的室内底噪句。

### 2.5 shots

| 字段 | 写法 |
|---|---|
| `duration` | 规划秒数，1~15。有台词时按配音实际长度自动加长（见第 3 节）。 |
| `shot_size` | `extreme-close-up` / `close-up` / `medium-close-up` / `medium` / `medium-wide` / `full` / `wide` / `establishing` / `over-the-shoulder`。 |
| `angle` | `eye-level` / `low-angle` / `high-angle`，只用于关键帧。 |
| `camera_en` | 一句完整英文：`The camera pushes in with small amplitude at slow speed.` |
| `characters` | 画面里出现的所有角色，包括背身和过肩的人。没列进来的人不会得到“闭嘴”约束。 |
| `outfit` | `{角色id: 服装key}`，决定用哪张设定图。 |
| `keyframe_prompt` | 首帧静帧：景别机位、每人位置/朝向/姿态/表情、前后景、光线，40~80 个词。 |
| `motion_prompt` | 镜头内发生的事：起点 → 唯一动作 → 终点，30~70 个词。为空时用 keyframe_prompt 代替。 |
| `end_state` | 可选，镜头结束时的状态，接在台词之后。 |
| `sfx` | 本镜头特有的拟音，完整英文句子，并入 `overall_soundscape`。 |
| `method` | 见下表。 |
| `transition` | `cut`（默认）/ `fade` / `dissolve` / `flash`。不是 `cut` 的镜头之后会另起新段。 |
| `seed` | 固定关键帧种子；为空时按镜头 id 自动算。 |

`method` 的取值（schema 里没有单独的 `i2v`，单镜无对白时 `auto` 就走 I2V）：

| 值 | 编排器的做法 |
|---|---|
| `auto` | 默认。和同场相邻镜头合并成 H3 Ref2VA 段；如果最后这一段只有 1 个镜头且没有台词，就改用 FL2VA I2V。 |
| `flf2v` | 单独成段，FL2VA 首尾帧。需要填写 `end_keyframe_prompt`，keyframes 会多生成 `<镜头>_end.png`。 |
| `t2v` | 单独成段，FL2VA 纯文生，不生成关键帧。适合空镜。 |
| `continue` | 单独成段，用上一段已选中那条视频的最后一帧作首帧，接着拍。上一段的选条会被锁定。 |
| `animate` | Wan Animate 2 动作迁移，需要 `driving_video`。video 阶段会跳过这段，按 [docs/03-工作流SOP.md](03-工作流SOP.md) 用 `workflows/12_wan_animate2_performance_transfer.json` 手动生成。 |

### 2.6 dialogue

```yaml
dialogue:
- speaker: lin_wan                 # 角色 id
  text: 这封信，写的是我的名字。      # 中文原文，逐字进入 <d>[Chinese] …</d>
  emotion: surprise                # 情绪标签，决定 IndexTTS-2.5 的情绪向量
  delivery: in a low, stunned whisper   # 英文表演提示，编译成 "says in a low, stunned whisper:"
  voiceover: false                 # 画外音：画面里所有人的嘴都不动
  emo_vector: null                 # 可选，8 维向量，覆盖 emotion
```

`delivery` 会直接接在 `says` 后面，所以要写成副词短语：`quietly and evenly`、`coldly, with restrained anger`。

`emo_vector` 的顺序固定为 **[happy, angry, sad, afraid, disgusted, melancholic, surprised, calm]**。各标签的默认向量来自 `aidrama/audio.py`，是经验起点，不是官方数值：

| emotion | 默认向量 | emotion | 默认向量 |
|---|---|---|---|
| neutral | [0,0,0,0,0,0,0,0.6] | surprise | [0.05,0,0,0.15,0,0,0.7,0] |
| happy | [0.7,0,0,0,0,0,0.1,0] | disgust | [0,0.15,0,0,0.7,0,0,0] |
| angry | [0,0.8,0,0,0.1,0,0,0] | contempt | [0.1,0.15,0,0,0.55,0,0,0.15] |
| sad | [0,0,0.6,0,0,0.3,0,0] | whisper | [0,0,0,0.1,0,0.2,0,0.5] |
| cry | [0,0,0.7,0,0,0.3,0,0] | fear | [0,0,0.15,0.75,0,0,0.05,0] |

不在表里的标签会退回 `neutral`，不会报错。`audio`、`duration`、`start` 由 voice 和 plan 自动填写，不用手写。

## 3. 写好镜头的规则

1. **一个镜头只做一个主动作。** 写法是“起点 → 唯一动作 → 终点”。H3 的高速运动容易糊、碎（H3 issue #74，见 [docs/research/07-运镜与动作控制.md](research/07-运镜与动作控制.md)）。
   - 差：`[lin_wan] stands up, walks to the shelf, pulls out a box, opens it and gasps.`
   - 好：`[lin_wan] reads the address on the envelope; her eyes widen slightly, her breath catches, and her fingers tighten on the paper.`
2. **时长。** 每镜 2~5 秒；每句台词不超过 16 个字，一个镜头最多 2 句。有台词时，镜头时长 = max(规划时长, 0.35 + 各句时长 + 句间 0.25 + 0.45)。例如 s01_01 规划 3.5 秒，配音 2.94 秒，0.35 + 2.94 + 0.45 = 3.74 秒，所以下一镜写成 `[Shot 2] At 00:03.740`。台词放不下就拆镜，不要让 TTS 加快语速。
3. **分段由代码决定。** 同一场里相邻、`transition: cut`、`method: auto` 的镜头会被合成一段，每段不超过 12 秒、4 个镜头、3 个角色、9 张参考图。单独成段的镜头不足 4 秒时按 4 秒生成，成片只取前 `planned` 秒，所以这类镜头的动作要在前半段完成。
4. **听的人闭嘴。** 编译器会给 `characters` 里本镜头不说话的人加一句 “does not speak; the lips remain completely closed”。最稳的还是在构图上避开：听者背对镜头、出画，或只露过肩轮廓。社区实测：不说话的人出画或背对镜头时 12/12 正确；同框都是正脸时，3 次里有 2 次口型落在错的人身上（zen 技能库数据，见 [docs/research/05-对白口型与数字人.md](research/05-对白口型与数字人.md)，未独立复现）。
5. **景别。** 对白用 `medium-close-up` / `close-up` 正反打；进场、空镜用 `establishing` / `wide`；两人同框用 `over-the-shoulder` 或 `medium-wide` 做前后景纵深，不要一字排开。同框最多 3 人。
6. **运镜 = 类型 + 幅度 + 速度。** 类型只用 push in / pull out、zoom in / out、pan、truck、tilt、pedestal、arc shot、tracking shot、static shot、shake slightly / strongly、POV、roll。幅度写 `with small/large amplitude`，速度写 `at slow/fast speed`，中等幅度和正常速度可以不写。按官方指南的意思：切镜要带来新信息（新主体、新空间、新状态）；只是距离或角度略变，就用运镜，不要切。
7. **情绪写成身体细节。** 用 jaw tightening、swallowing once、eyes drifting away，不要只写 sad、angry。
8. **竖屏构图。** 人物眼线在画面上 1/3；画面下方约 20% 留给字幕（字幕底边距 520px），关键动作不要放在最底部。遵守 180° 轴线：同一场里每个角色在画面左右的位置不变。
9. **避开 AI 弱项。** 手部特写、精细手指动作、吃喝、镜子、持续打斗、3 人以上肢体接触、需要看清的文字/手机屏幕/招牌。画面文字一律后期加；编译出的提示词每段都写明不出现字幕和画面文字。打斗、复杂走位改用 `method: animate`。

坏例子和改法：

| 问题写法 | 改法 |
|---|---|
| `characters: [lin_wan]`，但 keyframe_prompt 里有 `[gu_chen]` 背影 | 把 `gu_chen` 也列进 `characters`，否则不会生成他的闭嘴约束，也不会给他身份参考图 |
| `camera_en: push in, slow` | `The camera pushes in with small amplitude at slow speed toward her face.` |
| `motion_prompt: 林晚愣住了` | 英文，并写出可见动作：`[lin_wan] freezes; her breath catches and her eyes stay fixed on the envelope.` |
| 一个镜头 3 句台词、共 40 字 | 拆成两个镜头，正反打 |
| 两人正脸并排对话 | 改成过肩：说话的人正脸，听的人在前景背身 |

## 4. H3 提示词结构

### 4.1 FL2VA（单镜头：I2V / 首尾帧 / 文生）

三个字段，顺序固定：`integrated_multimodal_description`、`overall_soundscape`、`non_diegetic_music`。有参考图时，第一行先写一句参考图和时间轴的对应关系，空一行再接三个字段：I2V 写首帧在 0.00 秒；首尾帧写 Picture 2 落在时长秒数（保留两位小数）；文生不写。FL2VA 里不能出现 `<Subject>`、`<Audio>`、`<Video>`，人物用身份短语称呼。

真实输出 1：`ep01_g03`，s02_01 空镜，`method: t2v`：

```text
integrated_multimodal_description: [Shot 1] Live-action, cinematic, warm brass desk lamp as the key light with cool blue city light through the window; city lights twinkle softly beyond the glass while the desk lamp glows steadily in the empty office. The camera pushes in with small amplitude at slow speed toward the window. No subtitles, captions or on-screen text appear.

overall_soundscape: Low air-conditioning hum and muffled city traffic behind the glass.

non_diegetic_music: N/A
```

真实输出 2：FL2VA I2V。把 s01_04 的 `transition` 改成 `fade` 后，s01_05（顾沉沉默、无台词）单独成段，生成结果如下：

```text
For the target video, at 0.00 seconds into the target video, <Picture 1> (from [Shot 1]) is fully referenced.

integrated_multimodal_description: [Shot 1] Live-action, cinematic, starting exactly from <Picture 1> and keeping its characters, costumes, set and lighting consistent, low-key light from a green banker's lamp with cool blue moonlight from a high window; a tall man in his early 30s with short side-parted black hair, wearing a charcoal three-piece suit, white shirt without a tie, a silver wristwatch does not answer; his jaw tightens and he swallows once, eyes drifting away for a moment. The camera holds a static shot. a tall man in his early 30s with short side-parted black hair, wearing a charcoal three-piece suit, white shirt without a tie, a silver wristwatch does not speak; the lips remain completely closed. No subtitles, captions or on-screen text appear.

overall_soundscape: Quiet archive room tone with a faint ticking clock and the soft hum of an old lamp.

non_diegetic_music: N/A
```

可以看到，身份短语原样嵌入后，句首是小写，读起来也重复。结构没有问题，介意的话交给 LLM 扩写，或者写 `.manual.txt` 润色。

### 4.2 Ref2VA（多镜头 / 对白段）六段式

顺序固定：`subject_definitions` → `summary` → `retention_analysis` → `detailed_description` → `overall_soundscape` → `non_diegetic_music`。

| 段 | 编译器写什么 |
|---|---|
| subject_definitions | 每个角色一行 `<Subject N> (Sx) is the person in <Picture k>, 身份短语, wearing 服装.`；每张关键帧一行（属于哪个镜头、画面内容，最多 240 字符）；对白音轨一行 |
| summary | 方括号任务类型（`keyframe completion + reference generation + audio reuse`）+ 几镜头、谁出场、从哪张图开始、切到哪些图、`<Audio 1>` 提供台词 |
| retention_analysis | 角色 `fully_preserved`（脸、发型、肤色、体型、服装）；关键帧 `fully_preserved`（构图、站位、服装、光线）；对白音轨 `partially_copy`（逐字复用台词，其余声音另加） |
| detailed_description | 风格 + 光线开头，然后逐镜 `[Shot N]`：动作 → 运镜 → 台词 → 闭嘴声明 → end_state |
| overall_soundscape | scene.sound_en + 各镜 sfx |
| non_diegetic_music | 固定 `N/A`：配乐在后期由 MiniMax Music 3 生成并混音，不让 H3 自己加音乐 |

真实输出：`ep01_g02`（s01_04 + s01_05，林晚质问、顾沉沉默），全文如下：

```text
subject_definitions:
<Subject 1> (S1) is the person in <Picture 3>, a slender woman in her mid-20s with a low black ponytail, wearing an ivory silk blouse with a thin black ribbon tie, small pearl earrings.
<Subject 2> is the person in <Picture 4>, a tall man in his early 30s with short side-parted black hair, wearing a charcoal three-piece suit, white shirt without a tie, a silver wristwatch.
```

### 4.3 标签与时间规则

- **`<Picture N>` / `<Audio N>` / `<Video N>` 各自编号**，按节点连接顺序。本流水线的顺序是：先放各镜头关键帧（Picture 1..k，按镜头顺序），再放出场角色的设定图（每人 1 张，优先 `sheet_<服装>`，没有就用 `front`），图片总数不超过 9 张；`<Audio 1>` 是本段的 TTS 对白音轨。
- **只用来定义角色的图，不单独列一行**，写在 `<Subject N>` 的定义里（`is the person in <Picture 4>`）。这是官方 Ref2VA 指南的要求。
- **`<Subject N>`** 按角色在本段第一次出现的顺序编号。画外音说话人即使不在画面里，也会分到一个 Subject。
- **`(S1)(S2)`** 按本段里第一次开口的先后编号。两套编号规则不同：Subject 按出场顺序，S 按开口顺序。不开口的角色没有 S 编号，例如 `ep01_g02` 里顾沉是 `<Subject 2>`，但没有 S 编号。`retention_analysis` 里不写 S 编号。每段单独编号，同一个角色在不同段里的编号可能不同。
- **时间戳**：`[Shot 1]` 不带时间；之后写 `[Shot N] At MM:SS.mmm, the camera cuts to …`，严格递增，并且小于本段时长。编排器同时用 `MiniMaxH3AddGuide` 把每镜关键帧钉在 `frame_idx = round(切点秒 × 24)`。例如 `ep01_g01` 的三个锚点是 0、90（3.74 秒）、162（6.74 秒），总帧数 260（17k+5）。
- **台词**：`<d>[Chinese] 原文</d>`，逐字、按顺序，标点也不改；说话人、音色、语气都写在 `<d>` 外面。说话人第一次开口时带上 `voice_en`。
- **画外音**：`voiceover: true` 时编译为 `… (S1) says in an off-screen voiceover: <d>[Chinese] …</d> while the lips of everyone on screen remain completely closed.`
- **跨切台词**：官方格式里，一句台词跨过切点时，两边都用 `<scenetrans>` 标记；被片尾截断时用 `<cutoff>`。编译器不会生成这两种标记（分镜规则本来就不让台词跨切），确实需要时写在 `.manual.txt` 里。
- **声音**：官方指南把 `overall_soundscape` 写成 `N/A` 限于全程静音的情况，所以编译器总会写一句环境声；`non_diegetic_music` 固定写 `N/A`，不写的话模型可能自己加音乐。

### 4.4 本地 LLM 扩写（本地版 Context-IR）

MiniMax 官方的 H3-Context-IR 没有开源。本流水线的替代做法是：本地 LLM 以 `aidrama/prompts/h3_rewriter_system.md` 为系统提示词，只扩写画面、表演和声音细节，结构、标签、时间戳、台词、闭嘴声明一律不许动。扩写结果必须通过 lint，最多试 2 次；仍不通过就用确定性草稿，日志里会出现 `LLM 改写未通过校验，使用确定性版本`。

- 先运行 `python -m aidrama fetch-guides`，把官方 `base-en.txt` / `ref-en.txt` 下载到 `~/.cache/aidrama/h3-guides/`。下载后它们会附在扩写的系统提示词后面。
- 官方 Ref2VA 指南建议 `detailed_description` 写 350~500 个英文词。示例里的确定性草稿只有 155~287 词，扩写就是为了补足这部分细节。扩写后画质是否明显提升，没有在本地实测（未确认）。
- 不想用 LLM 扩写时，在工程目录的 `aidrama.yaml` 里写 `video: {refine_prompt_with_llm: false}`。

关于对白口型：默认做法是先用 TTS 配好音，再把整轨作为 `<Audio 1>`（`partially_copy`）交给 H3。H3 的口型能否严格对上外部音频，调研时只找到社区约 3 秒的小规模验证，本项目也没有在真机上测过（未确认）。口型不过关的处理（重抽、InfiniteTalk 兜底）见 [docs/05-质检与返工.md](05-质检与返工.md)。

## 5. 人工改写（.manual.txt）

**什么时候手改**：LLM 扩写反复不通过；某段要加特定的表演细节或 `<scenetrans>`；关键帧描述被截断，需要补全；抽了几条都在同一个地方出错，需要换个说法强调。

**步骤**：

```bash
cd <工程>/episodes/ep01/prompts
cp ep01_g02.draft.txt ep01_g02.manual.txt     # 或者从扩写后的 ep01_g02.txt 复制
# 编辑 ep01_g02.manual.txt
python -m aidrama video <工程> ep01 --only ep01_g02 --force     # 丢弃这段旧的抽卡结果重新生成
# 或者：python -m aidrama video <工程> ep01 --only ep01_g02 --takes 4   # 保留旧条，按新提示词补抽到 4 条
```

只有这段需要补抽或加了 `--force` 时，video 才会读 manual 文件。有 manual 文件时，每次仍会重写 `.draft.txt`，方便对照。

**不能改的东西**：字段名和顺序、`[Shot N]` 编号和时间戳、所有 `<Picture/Audio/Subject N>` 标签、`<d>` 里的台词。切点时间和 AddGuide 锚点是按 `project.yaml` 算的，只改文本里的时间戳，锚点不会跟着动；要改时长，请改 yaml 后重新 `plan`。

**lint 只提示，不拦截**。manual 文件有问题时，日志会打印问题，同时写进 `project.yaml` 这一段的 `prompt_issues`，但仍然照样提交生成。下面是一次真实日志（故意改错了台词、给 Shot 1 加了时间戳，而且用的是旧段号的草稿）：

```text
使用人工提示词 ep01_g02.manual.txt（注意：['[Shot 1] 不应带时间戳', '镜头数 2 与计划 1 不一致', '切镜时间必须递增且小于时长 4.62s: [0.0, 4.62]', "台词必须逐字、按顺序写在 <d>[Chinese] …</d> 中：期望 ['三年前寄出的信，为什么今天才到？']，实际 ['三年前寄出的信，为什么今天才送到？']", '引用了不存在的 <Picture 3>（只连接了 2 个）', '引用了不存在的 <Picture 4>（只连接了 2 个）']）
```

| lint 提示 | 原因与修法 |
|---|---|
| 缺少必需字段 / 字段顺序不对 | 字段名拼错或被删掉。FL2VA 三个字段，Ref2VA 六个字段，名字后面带冒号 |
| 缺少 [Shot 1] / [Shot 1] 不应带时间戳 | 第一镜必须写 `[Shot 1]`，不带 At |
| 镜头编号不连续 / 镜头数与计划不一致 | 增删了 `[Shot N]`。镜头数要和 `plan` 的结果一致 |
| 切镜时间必须递增且小于时长 | 时间戳被改乱了，照抄 draft 里的时间戳 |
| 台词必须逐字、按顺序写在 <d>[Chinese] …</d> 中 | 改了字、标点或顺序。台词要改就改 yaml 后重新配音 |
| 引用了不存在的 <Picture N> | 标签编号超出了实际连接的数量 |
| FL2VA 模式不能使用 <Subject>/<Audio>/<Video> 标签 | 单镜段不能用 Ref2VA 的写法 |
| 对白和画面文字以外出现了中文 | 描述部分混进了中文 |
| 还有未替换的 [角色id] 占位符 | 写成了 `[lin_wan]` 这种占位符，应该用 `<Subject N>` 或身份短语 |
| non_diegetic_music 为空 | 没有配乐也要写 `N/A` |

**段号会变**：段号（`ep01_g01`、`ep01_g02` …）是 `plan` 按顺序编的。改了时长、增删镜头、改了 transition 或 method 之后再 `plan`，后面的段号可能整体移位，旧的 `ep01_g02.manual.txt` 就会套到另一段上。上面那条日志就是这样来的：s01_04 改成 `fade` 之后，`ep01_g02` 从 2 镜变成 1 镜，旧 manual 文件被套上去，lint 报“镜头数 2 与计划 1 不一致”。每次 `plan` 后先看输出的段表，把不再对应的 manual 文件改名或删除。

**优先改 yaml 还是 manual**：凡是影响时长、参考图、台词、出场角色的修改，都改 `project.yaml`；manual 只用来调措辞。

## 6. 关键帧和设定图提示词

图像提示词都由 `aidrama/pipeline.py` 里的模板拼出来，你能控制的是 yaml 字段。默认引擎：Qwen-Image-2512 负责文生图（定妆照、场景图），Qwen-Image-Edit-2511 负责多参考编辑（设定图、关键帧），两者都是 Apache-2.0。

**定妆照（Qwen-Image-2512，1024×1536）**，真实输出：

```text

Plain light-grey studio backdrop, soft even studio lighting, photorealistic live-action film still, natural skin texture, cinematic lighting, shallow depth of field. A unique, distinctive, natural face; not a celebrity.
```

负向提示词用 ComfyUI 官方模板的中文负向词：`低分辨率，低画质，肢体畸形，手指畸形，画面过饱和，蜡像感，人脸无细节，过度光滑，画面具有AI感。构图混乱。文字模糊，扭曲`（50 步，cfg 4）。为了不撞“模板脸”，`appearance_en` 要写出可辨认的特征（痣、眼型、眉形），主角之间的脸型、发型要明显不同。

**角色设定图（Edit-2511，Picture 1 = 定妆照）**，真实输出：

```text
Character reference sheet of the person in Picture 1 on a plain light-grey background, three views standing side by side: full-body front view, full-body three-quarter view and full-body back view, wearing an ivory silk blouse with a thin black ribbon tie, small pearl earrings. Keep the face, hairstyle, skin tone and body shape of Picture 1 exactly. Even soft studio lighting, photorealistic live-action film still, natural skin texture, cinematic lighting, shallow depth of field. No text, no labels.
```

每套服装各生成一张 `sheet_<key>.png`。之后关键帧和 H3 的身份参考都用这张，所以设定图上的脸不对，一定要先在这一步修好（删掉 refs 重新 `cast`，或者换 seed）。

**场景图（Qwen-Image-2512）**：`Vertical film still of an empty location, no people: {description_en}. Eye-level wide view, {image_style_en}. No text.`

**镜头关键帧（Edit-2511 多参考，1088×1904）**，参考图按以下顺序装入（Edit-2511 最多 3 张）：

1. 画面里的角色，最多 3 人。每人一张 `sheet_<服装>`，没有就用 `front`。提示词里 `[角色id]` 换成 `the woman from Picture 1` / `the man from Picture 2`。
2. 还有空位时放场景图，并写 `The setting is the location shown in Picture N; keep its layout, props and lighting.`。3 个角色占满时没有场景图，改为写入 `Setting: {description_en}.`。
3. 每个角色加一句保持身份：`Keep the face, hairstyle and costume of the person in Picture N exactly.`

真实输出（s01_02，两人 + 场景图）：

```text
Vertical 9:16 live-action film still, medium-wide shot, eye-level angle. Medium-wide shot from behind the worktable: the woman from Picture 1 in the foreground on frame left, seen from behind over her shoulder, turning toward the doorway; the man from Picture 2 stands in the open doorway on frame right, backlit by a cold corridor light, his face half in shadow, rows of metal shelves between them. The setting is the location shown in Picture 3; keep its layout, props and lighting. low-key light from a green banker's lamp with cool blue moonlight from a high window. Keep the face, hairstyle and costume of the person in Picture 1 exactly. Keep the face, hairstyle and costume of the person in Picture 2 exactly. photorealistic live-action film still, natural skin texture, cinematic lighting, shallow depth of field. No text, no subtitles, no watermark.
```

Edit-2511 工作流的负向提示词为空（40 步、cfg 3，步数和 cfg 取自官方 int8 模板，见 `aidrama/graphs/qwen_edit.py` 文件头），所以要排除的东西只能写在正向里，也就是末尾的 `No text, no subtitles, no watermark`。

写 keyframe_prompt 的要点：

- 写站位、朝向、姿态、表情、前后景和光线，不写五官和服装。身份由参考图提供。Qwen 官方编辑提示词的思路也是：身份来自参考图时，直接指向那张图，用文字描述五官反而会让模型重画、降低相似度（见 `aidrama/prompts/qwen_image21_pe_edit.md`）。
- 用 frame left / frame right 写清左右，同一场保持一致（180° 轴线）。
- 有台词的镜头，首帧表情用中性或刚要开口的状态；情绪变化写在 motion_prompt 里。
- 关键帧描述会截断到 240 字符，写进 Ref2VA 的 `<Picture N>` 定义里，所以最重要的构图信息要写在前面。
- 只重做一张：`python -m aidrama keyframes <工程> ep01 --only s01_02 --force`；想固定满意的构图，在镜头上写 `seed:`。

可选引擎 Qwen-Image-2.1（`image.engine: qwen21`）是 **Qwen Research License，仅限非商用**。用它时，提示词里的 `Picture N` 会自动换成 `<imageN>`，关键帧参考图上限变为 9 张。商用项目不要开，见 [docs/07-合规与授权.md](07-合规与授权.md)。

## 7. 常见错误清单

| 现象 / 报错 | 原因 | 修法 |
|---|---|---|
| `check`：说话人 X 不在画面内 | 台词的 speaker 不在 `characters` 里 | 入画就加进 characters；画外音就设 `voiceover: true` |
| `check`：同框超过 3 人 | characters 超过 3 个 | 拆成“空镜 + 人物近景”，或者用过肩只露一人 |
| `check`：时长超出 1~15s | duration 写错 | 改成 2~5 秒 |
| video 报“确定性提示词未通过校验”+“出现了中文” | 英文字段里写了中文（常见于 motion_prompt、delivery、sfx、lighting_en） | 改成英文。只有 dialogue.text 和 action 能写中文 |
| “还有未替换的 [角色id] 占位符” | id 拼错，或者在 camera_en / sfx / lighting_en 里用了 `[id]` | 核对 id；那几个字段改用 he / she 或身份短语 |
| 读取 project.yaml 报错 | `[lin_wan] ...` 开头的值没加引号 | 用单引号包起来 |
| 口型落到听者脸上 | 听者正脸入画；或者听者没列进 characters，没有闭嘴约束 | 列进 characters；改构图（背身、过肩、出画）；不行就把两人拆到不同镜头 |
| 台词被改字、漏字、唱出来，或台词内容跑进画面 | H3 已知问题（issues #81、#68，见 [docs/research/07-运镜与动作控制.md](research/07-运镜与动作控制.md)） | 多抽几条，自动质检按字错率选优；仍不过就走 InfiniteTalk 兜底，见 [docs/05-质检与返工.md](05-质检与返工.md) |
| 改了台词，成片里还是旧配音 | 配音按文件缓存，已有 audio 的句子不会重配 | 删掉这句的 `audio:` 和 `duration:`，或者 `voice --force`；然后 `plan`、`video --force` |
| 写了 manual 文件但没生效 | 这段已经有足够的抽卡，video 直接跳过了 | 加 `--force`，或者用 `--takes` 补抽 |
| manual 文件套错了段 | 重新 `plan` 后段号移位 | 对照 plan 输出，改名或删除 manual |
| 换脸、服装漂移 | outfit key 写错；identity_en / outfits 和设定图不一致；keyframe_prompt 里又写了别的衣服 | 统一 outfit key；keyframe_prompt 不写服装；必要时重做设定图 |
| 画面出现字幕或乱码文字 | 删掉了 “No subtitles …” 那句，或者分镜要求看清文字 | 保留那句；画面文字一律后期加 |
| 片段里自带配乐 | `non_diegetic_music` 不是 `N/A` | 改回 `N/A`，配乐交给 music 阶段 |
| 动作做不完、变形、糊 | 一镜多个动作，或动作幅度太大 | 一镜一个动作；打斗用 `method: animate` |
| 短镜头的动作被剪掉 | 单独成段的镜头不足 4 秒，成片只取前 planned 秒 | 动作写在镜头前半段，或者把 duration 改到 4 秒以上 |
| 正反打方向乱（跳轴） | keyframe_prompt 里左右写反了 | 同一场里每人固定在 frame left 或 frame right |
| 情绪不对 | emotion 标签不在表里，退回了 neutral | 用表中标签，或写 `emo_vector`，或配 `voice.emotion_refs` |
| 三人镜头的关键帧场景不对 | 3 张参考位被角色占满，场景图没放进去 | 把 description_en 写具体；或者减到 2 人 |
| LLM 扩写总失败 | 本地模型太小，或者没有下载官方指南 | 先跑 `fetch-guides`；换更大的模型；或者关掉扩写，直接用确定性草稿 |
