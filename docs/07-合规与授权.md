# 07 合规与授权：在中国大陆发布 AI 短剧（2026-10）

> **这不是法律意见。** 本文是 2026-10-02 根据公开资料和本仓库代码整理的操作清单，目的是帮你少踩坑。法规、平台规则和模型许可证都会变，上线和商用前请以官方原文、平台合作方给的正式规范和律师意见为准。
> 标“未确认”的内容没有读到一手原文，只来自二手报道或推断。原始调研笔记见 [docs/research/01-行业现状与第一梯队标准.md](research/01-行业现状与第一梯队标准.md) 和 [docs/research/08-后期超分插帧合成.md](research/08-后期超分插帧合成.md)。
> 命令里的 `ad` 指命令入口：Windows 是 `.\aidrama.bat`，Linux 是 `./aidrama.sh`，也可以写 `python -m aidrama`（同 [docs/03-工作流SOP.md](03-工作流SOP.md)）。

aidrama 自动做三件事：每集成片右上角全程叠加显式标识“本内容由AI生成”；成片 MP4 写入 GB 45438-2025 附录 E 格式的 `AIGC` 元数据；默认流程只用原创生成的角色形象和“按文字描述设计”的音色。
**备案、封面和简介的标识、发布时的平台声明、各类授权、模型商用许可，都要你自己完成。**

### 1.2 每集发布前清单

逐项打勾；任何一项不满足，这一集就不要提交。

- [ ] **质量硬伤为零**：抖音审片标准列出的硬伤有：建模崩坏、肢体缺陷、穿模；音画或口型错位；机械配音；静止、重复、掉帧；双轨或错乱字幕；烂尾断更。逐条对照 [docs/05-质检与返工.md](05-质检与返工.md)。

- [ ] **授权齐全**：改编网文有书面授权；真人声音、真人表演有书面授权；音乐、字体可以商用。

## 2. 显式标识：GB 45438-2025 第 5.4 条与 aidrama 的实现

| 条款 | 国标要求（视频内容） | aidrama 的做法（`aidrama/assemble.py`） |
|---|---|---|
| 5.4 a) | 采用文字提示 | ffmpeg `drawtext` 叠加文字 |
| 5.4 b) | 同时含“人工智能”或“AI”，以及“生成”和/或“合成” | 默认文字“本内容由AI生成” |
| 5.4 c) | 位于视频起始画面，可另加在末尾和中间 | 不设起止时间，从第一帧显示到最后一帧 |
| 5.4 d) | 位于画面的边或角 | 右上角，距右边 40px、距顶 140px（1080×1920）。附录 C.4 的示例放在右下角，但竖屏平台右下角有点赞等按钮，所以不放那里 |
| 5.4 e) | 字型清晰可辨 | 白字 85% 不透明 + 2px 黑色描边；字体优先用安装脚本放在 `fonts/` 的思源黑体，找不到再用系统中文字体 |
| 5.4 f) | 文字高度不低于画面最短边的 5% | 字号取 `max(64, ceil(短边 × 5% ÷ 0.85))`，1080 宽时为 64。云端 mock 成片实测字形高约 61px（要求 ≥54px）。换字体后请截图自己量一次 |
| 5.4 g) | 正常播放速度下持续不少于 2 秒 | 全程显示，自然满足 |

`ep01.mp4`（烧字幕版）和 `ep01_clean.mp4`（无字幕版）**都带这个标识**；`.srt`、`.ass` 字幕文件里没有。aidrama 不加数字水印；GB 45438 第 6.2 条只说“准许”用数字水印，附录 A.2 写明对它不做要求。

**怎么改标识文字：**

- 生效顺序：`project.yaml` 里的 `series.ai_label` 优先，为空时才用配置里的 `post.ai_label`（`configs/default.yaml` 或工程目录的 `aidrama.yaml`）。代码是 `ai_label = series.ai_label or post.ai_label`。
- `series.ai_label` 默认就是“本内容由AI生成”，并且会写进 `project.yaml`，所以**只改 `post.ai_label` 不会生效**。要么直接改 `series.ai_label`，要么把它设成空字符串 `''` 再用 `post.ai_label`。
- 两处都为空时**不加显式标识**。不要这样做。
- 新文字必须同时含“AI/人工智能”和“生成/合成”。平台要求写“本作品含AI生成内容”，可以直接用。“AI辅助制作”不含“生成/合成”，不满足 5.4 b)；如果平台坚持这个写法，可以写成同时满足两边的文字，例如“AI辅助制作 含AI生成内容”（平台是否接受，未确认）。
- 文字里不要用半角冒号 `:`、单引号 `'`、反斜杠 `\`、百分号 `%`。它们在 ffmpeg 滤镜里有特殊含义：实测半角冒号会让冒号前的文字被吞掉，画面只剩后半截，**而且不报错**；百分号会报 `Stray %`。全角标点（`：`、`，`）没问题。
- 字号（`ai_label_size`）和位置不在配置文件里。要改，就改 `aidrama/assemble.py` 里的 `AssembleOptions.ai_label_size` 和 `drawtext` 的 `x=w-tw-40:y=140`；改完要保证标识仍在边角，字形高度仍不低于短边的 5%。

**需要你自己检查的：**

- 真机预览：右上角 y=140 的位置会不会被平台顶栏（搜索、频道切换等）挡住，没有在真机上确认。
- 剪映精修时，不要裁切或缩放画面，导致标识出画或变小；不要在标识上叠贴纸。
- 封面、海报同样要标（按 5.2：边或角，文字高度 ≥ 最短边 5%）。aidrama 不生成封面。
- 《微短剧发展管理办法》要求“每集、明显位置”。走 `ad assemble` 的每一集都会加；预告、花絮等不走 `assemble` 的视频要自己加。

## 3. 隐式标识：第 6.1 条与附录 E

**国标怎么规定：**
- 第 6.1 条：文件元数据隐式标识要有五个要素：生成合成标签、服务提供者、内容制作编号、传播服务提供者、内容传播编号。格式按附录 E；**一个文件里只保留一份**（6.1 c）。
- 附录 E：扩展字段名要含“AIGC”；值是一个 JSON 字符串，共七个字段。
- 附录 E j)：字段值只能用 GB 18030 码位 0x21、0x23–0x5B、0x5D–0x7E 的字符（即可见 ASCII 去掉双引号和反斜杠），以及转义的 `\"`。

**aidrama 怎么写：** 在 `assemble` 的最终编码时，用 ffmpeg 的 `-movflags +faststart+use_metadata_tags -metadata AIGC=<JSON>` 写入，位置是 MP4 的 `moov/udta/meta`（keys + ilst）。云端实跑的输出如下：

```json
{"AIGC":{"Label":"1","ContentProducer":"aidrama-local","ProduceID":"ep01-20261002150622-dfabb3d0","ReservedCode1":"fc43aa265715a89be4bf98cf5522ffcb7969b9fb","ContentPropagator":"aidrama-local","PropagateID":"ep01-20261002150622-dfabb3d0","ReservedCode2":""}}
```

| 字段 | 附录 E 的含义 | aidrama 的取值 |
|---|---|---|
| `Label` | 1 = 属于生成合成内容，2 = 可能是，3 = 疑似 | 固定 `"1"` |
| `ContentProducer` | 生成合成服务提供者的名称或编码 | 配置项 `post.aigc_producer`，默认 `aidrama-local` |
| `ProduceID` | 提供者对该内容的唯一编号 | `<集号>-<年月日时分秒>-<8 位随机十六进制>`，**每次运行 `assemble` 都会变** |
| `ReservedCode1` | 提供者自用的完整性保护信息（附录 F.4 的示例是对元数据做杂凑） | 前三个字段的 SHA-1。没有密钥，只能发现无意的损坏，防不住故意篡改 |
| `ContentPropagator` | 内容传播服务提供者的名称或编码 | 首次写入，按附录 E 注 1 与 `ContentProducer` 相同 |
| `PropagateID` | 内容传播编号 | 首次写入，与 `ProduceID` 相同 |
| `ReservedCode2` | 传播方自用 | 空字符串，留给平台 |

**设置 `post.aigc_producer`：**
- 只能用英文字母、数字和 `-`、`_`、`.` 这类可见 ASCII，不能有空格或中文。
- 代码会把不合规的字符换成 `_`；如果整串都是中文，会退回默认值 `aidrama-local`。
- 建议填公司或工作室的英文简称，写在工程目录的 `aidrama.yaml` 里：

```yaml
post:
  aigc_producer: mystudio
```

全国网安标委有一份《服务提供者编码规则》实践指南（TC260-PG-20252A），本次没读原文。名称是否必须按它编码，未确认。

**验证（Linux 和 Windows PowerShell 都能用）：**

```bash
ffprobe -v quiet -show_entries format_tags=AIGC -of default=nw=1:nk=1 projects/myshow/episodes/ep01/out/ep01.mp4
```

- 打印出上面那样一行 JSON，且 `Label` 为 `1`：写入成功。
- 什么都不打印：文件里没有隐式标识。

想查得更严，可以用第三方校验库 AigcTotal（C#/.NET）的 `aigc-report ep01.mp4`。它按附录 E 逐字段检查，能发现“一个文件里有多份标识”这类问题。本仓库没有集成它，也没在本机跑过。

**用剪映等外部工具再剪过之后，要补写元数据。** 外部工具导出时通常会丢掉自定义元数据；剪映导出是否会自带一份 AIGC 标识，未确认。下面的命令在 Linux / WSL / Git Bash 下实测可用，作用是：把 aidrama 原片里的那份标识原样搬到新文件上，同时清掉新文件原有的全局元数据，保证全文件只剩一份。

```bash
SRC=projects/myshow/episodes/ep01/out/ep01.mp4     # aidrama 合成的原片
EDIT=ep01_jianying.mp4                              # 外部工具导出的版本
AIGC=$(ffprobe -v quiet -show_entries format_tags=AIGC -of default=nw=1:nk=1 "$SRC")
ffmpeg -i "$EDIT" -map 0 -c copy -map_metadata -1 -movflags +faststart+use_metadata_tags -metadata "AIGC=$AIGC" ep01_final.mp4
```

- `use_metadata_tags` 不能省。不带它，ffmpeg 会悄悄丢掉 `AIGC` 这种自定义键（ffmpeg 6.1 实测）。
- Windows PowerShell 5.1 传参时会吃掉 JSON 里的双引号，建议在 WSL 或 Git Bash 里执行（未在 Windows 上实测）。

**要知道的限制：**

- 平台按《标识办法》第六条核验元数据，并“添加传播要素”，可能改写 `ContentPropagator`、`PropagateID`、`ReservedCode2`；平台转码也可能把元数据整个清掉。这是正常现象，你的责任是上传的文件里有标识。
- 把标识写在 MP4 的 keys/ilst 位置，依据的是第三方校验库对 TC260-PG-20257A 指南的实现，指南原文没读到（未确认）。平台检测工具实际读哪个位置，以审核结果为准。
- 用付费 API（Seedance、可灵、H3 Context-IR / Regenerate-2K 等）生成的素材，自带的可见水印、数字水印和元数据**不要去除**（《标识办法》第十条、《深度合成管理规定》第十八条）。不要用 VOID 之类的修补模型擦水印。
- aidrama 合成时会给成片写入自己的一份 AIGC 元数据，因为标准要求全文件只留一份。请把原始 API 文件和它的元数据原样留档。这种“合成后重新标识”算不算改写他人标识，是灰色地带（未确认）。

### 4.1 MiniMax H3：商用前必须自己读原文

- 官方 README 只给了 HF 上 LICENSE 的链接（https://huggingface.co/MiniMaxAI/MiniMax-H3/blob/main/LICENSE），本次没能读到原文。
- **二手报道**（SCMP 等）的说法：
  - 年营收 2000 万美元以下可以免费商用；
  - 美国、欧盟、英国、韩国被排除在授权地域之外，中国大陆不在其列；
  - 产品中要标注 “MiniMax H3”；
  - 不得用 H3 的输出训练其他模型。
- **ComfyUI 官方文档**（H3 总览页，2026-10）的说法：本地生成的输出用于商业用途，需要 MiniMax 商业许可证，通过唯一官方经销商 Comfy 购买（https://comfy.org/minimax/license）；在 Comfy Cloud 上生成的内容已含商用权。同一套文档讲 Music 3 时写明“年营收 2000 万美元以下可商用”，讲 H3 时却没写营收门槛。
- 两种说法冲突（未确认）。保守做法：
  - 商用项目按“需要购买商业许可”准备预算，或者书面向 MiniMax 确认（README 里的联系邮箱 model@minimax.io）；
  - 在片尾或简介注明“部分画面由 MiniMax H3 生成”，成本很低，可以先做上。
- 提示词指南：MiniMax 官方 H3 提示词指南没有附许可证，所以本仓库不附带原文。`ad fetch-guides` 只把它下载到本机缓存自用，不要再分发。

### 4.2 MiniMax Music 3

- ComfyUI 官方文档：Community License 允许年营收低于 2000 万美元的公司商用；超过门槛要通过 Comfy 购买 MiniMax 商业许可。

### 4.3 IndexTTS-2.5（bilibili 模型使用许可协议，已读原文）

  - 本仓库 [docs/01-调研报告.md](01-调研报告.md) 和调研笔记里写的“10 亿元”，以此处为准更正。

## 5. 肖像、声音与原创性

**肖像**

- 不要用明星、网红、素人的照片做参考图（`characters[].refs`、关键帧参考都算），不要换脸，提示词里不要写“像某某”。
- 相关判例和事件：
  - 北京互联网法院 2026-03 认定，AI 换脸“神似演员”也构成侵权，判断标准是“可识别性”；
  - 《桃花簪》盗用博主写真生成反派角色，全面下架，出品方被停更 15 天；
  - 最高法 2026-09-07 发布涉 AI 纠纷审理意见（24 条），具体条文本次没读。
- Wan Animate 2 迁移真人表演时，驱动视频里演员的脸会被换成你的角色，但动作表演仍来自他本人，要有书面授权。H3 Ref2VA 的参考视频（最多 3 段）同理，不要拿影视剧片段当参考。

**声音**

- 默认流程不克隆任何真人：每个角色的音色由 Qwen3-TTS VoiceDesign 按文字描述“设计”出来（`voice.description` → `assets/characters/<id>/voice.wav`），再交给 IndexTTS-2.5 配音。
- 如果你在 `voice.ref_audio` 或 `voice.emotion_refs` 里放了真人录音（配音演员、你自己、朋友），必须先拿到本人的书面授权。授权里写清：用途（AI 声音合成）、作品范围、平台、期限、能否商用。
- 明星、主播、影视剧原声一律不用。虞书欣“融脸 + 声音”争议说明，声音同样有风险。民法典规定对自然人声音的保护参照肖像权（第一千零二十三条，本次未在线核对条文）。
- 写进 H3 提示词的英文音色描述（`voice.voice_en`）也不要写成“像某位名人”。

**避免“AI 模板脸”**

- 红果 2026-08-03 起：同剧主角必须有独立五官，不能只换发型和服装；跨剧人脸相似度超过 65% 直接驳回。
- 写 `appearance_en` 时，给出能把人区分开的具体特征：脸型、眼型、眉形、痣或疤、发际线、年龄感。不要只写 “beautiful, perfect skin” 这类通用词。示例工程《第七封信》里林晚的“左眼下一颗小泪痣”就是这类特征。
- aidrama **没有内置人脸相似度检测**。`ad cast` 出图后，把所有主角的 `front.png` 并排看一遍，再和你已上线的作品、当红 AI 剧的主角比一比；有条件的话，可以用任意人脸比对工具自查。
- 同一 IP 的续季沿用原角色，会不会被跨剧相似度规则误伤，未确认，提前和平台确认。

**剧本、音乐和其他素材**

- 改编网文、漫画要有书面授权；LLM 生成的剧本要人工改写定稿，并保留修改记录。
- BGM 用 MiniMax Music 3 生成，或用正版曲库；不要用热门歌曲。
- 字体：字幕和标识用思源黑体（OFL）。换别的字体前，先确认商用授权。

## 6. 留档建议

这些文件同时证明三件事：**原创**（没有挪用他人形象）、**合规**（有标识、有授权）、**可复现**（方便返工和平台申诉）。aidrama 已经把大部分写进工程目录，你要做的是别删、定期备份。

| 保留什么 | 位置 | 证明什么 |
|---|---|---|
| 工程主文件 | `project.yaml` | 全部设定、分镜、台词，每条抽卡的路径、种子（`seed`）、预设和选条记录 |
| 参数覆盖 | `aidrama.yaml`，以及你改过的 `configs/default.yaml` | 用了哪些模型、预设和标识设置 |
| 实际提交的工作流 | `graphs/*.json` | 每次提交给 ComfyUI 的完整 API 工作流，含模型文件名、种子和提示词，可以直接拖回 ComfyUI 复现 |
| 提示词 | `episodes/<ep>/prompts/`：`.txt` 是实际使用的，`.draft.txt` 是确定性版本，`.manual.txt` 是人工覆盖 | 人工创作投入和修改过程 |
| 角色与场景资产 | `assets/characters/<id>/`（定妆照、设定图、`voice.wav`）、`assets/locations/<id>/` | 角色是生成的原创形象，不是照片；音色是设计出来的 |
| 全部抽卡和中间产物 | `episodes/<ep>/` 下的 `keyframes/`、`segments/`、`audio/`、`qc/`、`final/`、`review.html` | 生成过程和人工选条 |
| 成片与元数据 | `episodes/<ep>/out/` 下全部文件，加上 `ffprobe` 打出来的 AIGC 那一行 | 交付的是哪个文件、`ProduceID` 是什么 |
| 授权文件 | 自建 `rights/` 文件夹：IP 授权、配音和表演授权、音乐授权、模型商业许可、备案材料和备案号 | 授权链完整 |
| API 原始素材 | 付费 API 生成的原文件，保持原样 | 外部素材的来源和原有标识 |

**操作建议：**

1. `project.yaml`、`aidrama.yaml`、`graphs/`、`prompts/` 都是文本，体积小，用 git 管理就能追溯每次改动。图片、音频、视频体积大，放到另一块盘或 NAS，按集打包备份。
2. aidrama 只把运行过程打印到终端，不写日志文件。想保留，Linux 下可以用 `ad run projects/myshow ep01 2>&1 | tee -a run.log`。
3. 每集交付时，把 AIGC 那一行存成文本，并记下成片的 SHA-256：

   ```bash
   ffprobe -v quiet -show_entries format_tags=AIGC -of default=nw=1:nk=1 ep01.mp4 > ep01_aigc.txt
   sha256sum ep01.mp4 >> ep01_aigc.txt
   ```

   `ProduceID` 每次 `assemble` 都会变，以实际交付的那一次为准。
4. 记下当时的软件和模型版本：ComfyUI 版本号、`configs/models.yaml`、`pip freeze` 的输出。许可证也会更新（IndexTTS 协议第 8 条说新版不溯及既往），所以把下载时的 LICENSE 文本一并存下来。
5. 保存多久：至少保存到这部剧下架之后。《标识办法》第九条要求服务提供者在提供不含显式标识的内容时，相关日志留存不少于六个月；这条不直接约束自制自用，只能作为留存时长的参照。
