# 04-角色一致性

> 原始调研笔记（2026-10-02，云端调研时整理）。正文结论已汇总进 docs/01-调研报告.md；这里保留细节与出处，标“未确认”的地方没有独立核实。

> 调研维度：角色/场景/服装一致性（图像定妆与编辑、视频主体一致性、角色 LoRA 训练、业内资产化流程）

## 结论
结论：截至 2026-10-02，在 5090 本地做出第一梯队的一致性，靠的不是某一个模型，而是一套组合流程：角色/服装/场景资产库 + 多参考图像编辑 + 角色 LoRA + 参考生视频（R2V）+ 尾帧续接 + 质检闭环。

【图像端】
- 主力（开源、可商用）：Qwen-Image-Edit-2511（2025-12-23，Apache-2.0，20B）。支持多图参考，多人同框一致性有提升，内置打光和换视角能力，ComfyUI 原生支持；用 int8_convrot 版约 20GB，32GB 显存可跑，配 Lightning LoRA 只需 4 步。
- 能力最强的新开源模型：Qwen-Image-2.1（2026-09-20）。7B DiT + Qwen3-VL-8B，最多 10 张参考图，原生 2K，支持 RGBA；官方文档给的 5090 速度是 1MP 约 0.3 s/it。最大风险：许可证是 Qwen Research License，只能非商用，商用要另找阿里授权。
- 同样不能商用：FLUX.2 dev 和 klein-9B（FLUX 非商用许可）。klein-4B 是 Apache 且很快（5090 上约 1.2 s），但身份保真度偏弱。
- 开源备选：HiDream-O1（MIT，8B）、FireRed-Image-Edit-1.1（Apache，主打身份一致性）、JoyAI-Edit-Plus、Mage-Flow-Edit。
- 定妆照文生图：Z-Image、HiDream-O1、Qwen-Image-2512。
- 云端兜底：Nano Banana Pro/2（最多 14 张参考）、Seedream 5.0、GPT Image 2/2.5，业内常用来出定妆照和三视图。

【视频端】
- 2025 年那一代（基于 Wan2.1-14B 的 Phantom、VACE、MAGREF、Stand-In、Lynx、BindWeave、HuMo；OpenS2V 总分约 55-58%）已退居备选。
- 本地最强的参考生视频方案：MiniMax H3 Ref2VA（2026-08-03 开源）。参考上限为 9 图 + 3 段视频 + 3 段音频，原生音频，ComfyUI 原生支持；AddGuide 节点可以把关键帧钉在任意一帧。
- 次选：LTX-2.5 原生多镜头（跨镜头保持角色、光线、音色）；LTX-2.3 ID-LoRA（脸和声音一起锁）。
- 动作戏：Wan-Animate-2 和 SCAIL-2 可以做"真人表演 → AI 角色"的迁移。
- 闭源：业内仍认为 Seedance 2.x 的写实真人效果最好。

【LoRA 训练】
ai-toolkit、musubi-tuner、DiffSynth-Studio 都已支持 Qwen-Edit-2511、Qwen-Image-2.1、Z-Image、HiDream-O1、MiniMax H3（含 Ref2V 和身份 teacher matching）。5090 配合 fp8/int8 + block swap 可以训练。

【业内流程与红线】
标准流程：定妆照 → 三视图/表情/服装卡（每张带 ID）→ 场景 plate → 分镜关键帧 → 首帧或参考生视频 → 用上一镜实际尾帧续接 → 人脸相似度检查 + VLM 检查服装道具。
红果规定跨剧人脸相似度超过 65% 直接驳回，所以角色脸必须原创，主角之间五官也要能区分。

### Qwen-Image-Edit-2511
- **category**：图像编辑/多参考一致性（主力，可商用）
- **developer**：Alibaba Qwen（通义千问）
- **release_date**：2025-12-23
- **open_weights**：yes，Apache-2.0
- **quality_evidence**：官方：漂移更少、角色一致性更好、多人合照高保真融合，并把社区的打光 LoRA 和新视角 LoRA 合进了基座。同系列 T2I 模型 Qwen-Image-2512 在 AI Arena 上 1 万多轮盲测中是最强开源模型。ComfyUI 模板描述为“Ideal for character-consistent portrait editing”。另有 Lightning 4 步加速和多视角 LoRA（fal）。
- **repo_ids_and_files**：Qwen/Qwen-Image-Edit-2511；ComfyUI 版 Comfy-Org/Qwen-Image-Edit_ComfyUI: split_files/diffusion_models/qwen_image_edit_2511_bf16.safetensors 或 qwen_image_edit_2511_int8_convrot.safetensors；文本编码器 Comfy-Org/HunyuanVideo_1.5_repackaged: qwen_2.5_vl_7b_fp8_scaled.safetensors；VAE: Comfy-Org/Qwen-Image_ComfyUI qwen_image_vae.safetensors；加速 LoRA: lightx2v/Qwen-Image-Edit-2511-Lightning（Qwen-Image-Edit-2511-Lightning-4steps-V1.0-bf16.safetensors）；多视角 LoRA: fal/Qwen-Image-Edit-2511-Multiple-Angles-LoRA（qwen-image-edit-2511-multiple-angles-lora.safetensors）
- **vram_5090**：20B MMDiT。int8_convrot 约 20GB，加 7B VL 编码器（fp8 约 9GB），由 ComfyUI 动态卸载，32GB 可用；bf16 约 41GB，需要靠 128GB 内存做 offload，会明显变慢。耗时（估算，未实测）：1MP、4 步 Lightning 每张约 3-8 秒；20-40 步无加速每张约 30-60 秒。训练：musubi 用 fp8_base+fp8_scaled 约 30GB，再加 blocks_to_swap 16 约 24GB。

- **strengths**：可商用；多图参考（官方 3 张，musubi 实测任意张数，但只确认 3 张正确）；中文文字渲染强；LoRA 生态最大（换角度、打光、next-scene 等）；三大训练框架都支持 edit-2511。

## 推荐做法
- **stage**：S1 原创角色脸与定妆照（文生图） ；**primary**：Z-Image（Base 用于多样性抽脸，Turbo 用于快速迭代），Apache-2.0 ；**alternatives**：HiDream-O1-Image（MIT，2K，AA 首次上榜第 8）；Qwen-Image-2512（Apache）；云端兜底 Seedream 5.0 / Nano Banana Pro ；**rationale**：这一步要的是多样、原创、有辨识度的脸，用来避开红果跨剧相似度超过 65% 驳回和“模板脸”。Z-Image 可商用、速度快、多样性高，也是最成熟的 LoRA 底模；HiDream-O1 适合要 2K 写实的情况。
- **stage**：S2 角色设定卡（三视图、表情、每套服装定装） ；**primary**：Qwen-Image-Edit-2511（int8_convrot）+ Multiple-Angles LoRA + Lightning 4 步，image1 固定为定妆照 ；**alternatives**：FireRed-Image-Edit-1.1（Apache，主打身份保持和妆容）；Qwen-Image-2.1（10 张参考、2K，效果最好，但只能非商用，商用需先拿到阿里授权）；云端 Nano Banana Pro/2 三视图模板 ；**rationale**：在可商用的开源模型里，2511 多图一致性、多视角和打光能力最全，ComfyUI 原生支持，32GB 能跑，三大训练框架都支持，后续可以直接在同一模型上训练编辑 LoRA。
- **stage**：S3 角色 LoRA（最强身份锁） ；**primary**：每个主角在 Qwen-Image-2512 或 Z-Image 上训练一个图像角色 LoRA（用 musubi-tuner 或 ai-toolkit，开 fp8 + block swap），关键角色另用 musubi 的 subject_ref teacher matching 训练 H3 身份 LoRA ；**alternatives**：Qwen-Image-Edit-2511 编辑 LoRA（配对数据）；HiDream-O1 LoRA；LTX-2.3 LoRA（32GB low-VRAM 配置）；DiffSynth 的 H3 适配器路线 ；**rationale**：多参考编辑能挡住大部分漂移，但侧脸、远景、表情夸张的镜头仍会跑脸，所以长系列（60 集以上、多季）需要 LoRA 做底线保障。5090 用 fp8/int8 + block swap 训练 20B 级模型约 24-30GB。H3 视频 LoRA 还处于实验阶段，只给头部角色使用。
- **stage**：S4 场景 plate 与分镜关键帧（多人 + 场景 + 服装） ；**primary**：Qwen-Image-Edit-2511：参考图依次为角色设定卡、服装卡、场景 plate，叠加角色 LoRA；9:16 先出约 1MP（如 768x1344 或 896x1600），需要时再放大 ；**alternatives**：Qwen-Image-2.1（获得授权后可做 2K、10 张参考的一镜合成）；JoyAI-Edit-Plus（多机位 plate）；Bernini-R 统一光线 ；**rationale**：关键帧决定视频的起点，一致性问题最好在图像阶段就修掉；先单独生成场景 plate 并复用，才能保证同一场的空间和光线连续。
- **stage**：S5 视频主体一致性（图生视频/参考生视频） ；**primary**：MiniMax H3：常规镜头用 FL2VA 首帧（或首尾帧）；身份或服装要求高的镜头用 Ref2VA，参考上限 9 张，ref_image_size=max，20-25 步不开 Lightning；多镜头用 AddGuide 在任意帧锚定关键帧；同一连续时空的相邻段用上一段尾帧（加音频）续接 ；**alternatives**：LTX-2.5 原生多镜头 / LTX-2.3 ID-LoRA；Wan-Animate-2 或 SCAIL-2（真人表演驱动的动作戏）；Wan2.1 VACE + ID-V2V 修脸；云端 Seedance 2.x R2V 用于写实正片的高难镜头 ；**rationale**：H3 是目前唯一开源、可在 5090 本地运行、能同时用多图、视频、音频做参考的模型，ComfyUI 原生支持且训练生态齐全。但写实真人质量业内仍认为不如 Seedance，商用也需要另买许可，所以建议本地 H3 跑大部分镜头，最关键的写实镜头上云兜底。
- **stage**：S6 一致性质检闭环 ；**primary**：逐镜抽帧算人脸嵌入余弦相似度，同角色设阈值，跨剧和对明星另设上限；用 Qwen3-VL 按服装、道具、场景连续性锁清单逐项核对；不合格的局部用 H3 latent noise mask 或 Qwen-Edit 重生成 ；**alternatives**：ID-V2V 事后修脸；人工抽检 ；**rationale**：抖音和红果把“建模崩坏、换脸漂移、跨剧相似”列为硬伤，自动化质检可以把抽卡成本压到最低。

## 关键技术
- 资产化（业内标准）：每个角色固定一套资产包——正面/3-4侧/正侧/背面四视图 + 5-8 种表情 + 每套服装全身定装照（服装单独编 ID，如 C01-服装A）+ 结构化外貌描述（脸型、眼型、发型、肤色、标志道具、配色）。统一灰背景、统一柔光，记录 seed、prompt、模型版本，留作原创证明。
- Qwen-Image-Edit-2511 / 2.1 的提示词写法：按序号点名参考图，并写明保留什么、改什么。例如“保持<image1>中人物的五官、发型、体型和姿势不变，把<image2>的浅蓝色牛仔衬衫穿到人物身上，背景替换为<image3>的场景”。image_1 永远放身份锚点（定妆照）。
- Qwen-Image-2.1 编辑的速度杠杆是 resolution（像素预算）：设为 1024 时约 1MP、5090 上约 0.3 s/it；设为 0 时会按原图尺寸采样（12MP 约 6 s/it）。局部换衣、改色 4-8 步即可，整帧重绘需要 25 步以上，手指等细节需要约 30 步。cfg 保持 1，最多 2。
- ComfyUI 中优先用 int8_convrot 权重：官方说明比 fp8 质量更好，多数 GPU 上也更快，LoRA 可以重新量化。注意 H3 的 int8 版不能配 Comfy Kitchen attention（会报对齐错误），要么用默认 attention，要么换 bf16 权重。
- H3 Ref2VA 写法：每个输入按连接顺序用 <Picture N>、<Video N>、<Audio N> 引用，并给每个参考分配职责（身份、服装、场景、运镜、音色）。按官方 ref 指南结构写：subject_definitions → summary → retention_analysis（写明 <Subject 1>: fully_preserved - 保留身份、发型、服装）→ detailed_description → overall_soundscape。
- H3 参数：9:16 原生画布为 768x1344（Resolution Selector 设 0.98MP，不要用 1.0MP）；帧数取 17k+5（124 帧约 5 秒）。对身份要求高的镜头关闭 Lightning 4 步 LoRA，用 20-25 步（4 步时参考几乎不起作用）。ref_image_size=max（短边最高 2048）能增强身份保真。
- H3 多镜头和续接：用 MiniMaxH3AddGuide 把关键帧钉到 frame_idx=round(秒×24)，可链式叠加多个。续接时把上一段最后 22 帧连同音频接到 frame 0。只接到 AddGuide 的图对文本编码器不可见，需要同时接入 ref_images 槽位，提示词才能引用到。
- 连续性锁：服装、道具的颜色、材质、形制等跨镜头不变的事实，在每一镜提示词里逐字重复，不要指望参考图或模型自己记住（zenstory drama-skills 的规则）。同一场所有镜头写同一句画风和同一句光线描述。
- 场景与光线连续性：每场戏先生成 1 张场景 plate（建议同时出 3-5 个机位，可用 JoyAI 或 Qwen-Edit 换视角），所有镜头都以它为参考；遵守 180 度轴线和统一光源方向；光线跳变用 Bernini-R、Qwen-Edit-2511 内置打光或 SCAIL-2 relighting LoRA 统一。
- 镜头层面避坑：每镜只放一个主动作；对白镜头用中近景正反打；3 人以上的肢体接触、手部特写、镜面、画面内文字一律少拍，文字全部在后期合成；多人同框用纵深的过肩构图；复杂动作用 Wan-Animate-2 或 SCAIL-2，先由真人或替身拍一段驱动视频。
- 角色 LoRA 数据集（经验值）：每个角色 20-40 张，包括 3-4 个角度、多种表情、近中远景、2-3 种光线；服装要么和角色分开打标签，要么分开训练服装 LoRA。caption 只写可变要素（动作、场景、服装），不写固定的外貌特征，并加触发词。rank 16-32，约 1500-3000 步，每 250 步存一次 checkpoint 做对比。
- 5090 训练参数：musubi 训 Qwen-Image 系用 --fp8_base --fp8_scaled，再加 --blocks_to_swap 8-16，约 24-30GB；Wan2.2 加 --fp8_base 和 block swap；H3 用 pruned INT8 DiT + NVFP4 编码器（--nvfp4_scaled_mm 走 Blackwell FP4），身份训练用 teacher matching subject_ref（--h3_teacher_condition_sigma_max 保持 1.0）。LTX 用官方 t2v_lora_low_vram.yaml（int8-quanto、adamw8bit、rank 16）。
- 加速：SageAttention 或 comfy-kitchen attention（--use-ck-attention）大约提速 2 倍；H3 长片段可开 Model Sparse Attention（sol-attn，start 0.2-0.4，end 0.9-1.0，tau 默认 1.3）；Qwen-Image-2.1 编辑可开 KV cache（device=auto，dtype 选 int8 基本无损）。
