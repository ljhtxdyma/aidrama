# 07-运镜与动作控制

> 原始调研笔记（2026-10-02，云端调研时整理）。正文结论已汇总进 docs/01-调研报告.md；这里保留细节与出处，标“未确认”的地方没有独立核实。

## 综述

**研究条件说明**：本次只完成了 6 次 WebSearch，第 7 次起提示整个会话的搜索额度（200 次）已经用完，所以没能做到要求的 20 次以上。Reddit、知乎、B 站、arXiv、docs.comfy.org、blog.comfy.org、minimax.io 和 huggingface 都被出口代理拦截，无法读取。能访问的只有 GitHub，所以主要证据来自一手源码和官方仓库：
- ComfyUI 源码：0.38.0，提交 65787d6，日期 2026-10-01。
- Comfy-Org/workflow_templates 的 `index.json`，含模板日期和使用量。
- 各模型的官方仓库 README 和 GitHub issues。

社区口碑部分（Reddit、知乎、B 站）基本缺失，下文标注了“未确认”。

**结论**

1. **MiniMax H3**
   - **定位**：本地对白镜头的第一选择。它把视频和 32kHz 立体声一起生成，单段 4–15 秒，24fps，短边 768。最大画幅 768×1344，正好是 9:16 竖屏。
   - **中文能力**：官方写明“稳定支持 11 种语言，含中文”，对白用 `<d>[Chinese]…</d>` 加说话人编号 (S1)(S2) 来写。
   - **镜头语言**：一次生成里可以用 `[Shot n] At 00:03.500, the camera cuts to…` 做多镜头剪切，用 `<scenetrans>` 让一句台词跨过剪切点。这对正反打很关键。
   - **和海螺的关系**：它是海螺 Hailuo 产品线 H3 的底座。官方 README 的在线入口就是 hailuoai.video，社区俗称 Hailuo 3.0。但开源的只有 H3-Base：负责理解复杂多模态输入的 H3-Context-IR 和 2K 重生成模块仍只走 API。经 fal 后训练的 H3 Max 是闭源的。所以它不等于完整的海螺产品。
   - **榜单**：Artificial Analysis 上，文生视频 v2.0 排第 4（Elo 1139）；图生视频 v1.0 排第 2（1181，第 1 是 H3 Max 的 1195）；视频编辑榜发布时 MiniMax 自称第 1（1130），后来另有来源显示第 2（1129）。这些数字来自搜索摘要，是二手数据。
   - **弱点**（来自 GitHub issues）：高速运动会碎、会糊（#74）；本地 ComfyUI 下 Ref2VA 参考保真度下降（#84）；台词内容会“变”到画面里（#81）；有时把台词唱出来（#68）。所以打斗不要硬靠 H3。

2. **LTX-2.5（2026-08-11）**
   - 官方模板明确写了“原生多镜头（native multishot）”、首尾帧生成（FLF2V）、自动时长、扩散式视频解码器（脸部更清晰）、原生 4K 和 HDR。
   - 已知问题：同框 3 个主体时身份和台词绑定会突然崩掉（#320）；会出现不想要的烧录字幕（#319）；2.x 版本生成中文字幕时会乱码。
   - 中文对白质量没找到证据，未确认。

3. **真人表演驱动**
   - **Wan Animate 2**（2026-08-07，Apache-2.0）：直接吃驱动视频，不需要提取骨骼，能迁移面部表情、身体和手部动作，背景和机位用文字控制。每段 81 帧（约 3.4 秒），需要串接。有人用 insightface 测出非正脸时身份相似度掉到 40–50%（#6）。
   - **SCAIL-2**（2026-06-09，Apache-2.0）：有“替换”和“驱动”两种模式，支持多参考图和多人。有人反馈皮肤质感偏假（#20、#23）、换脸后脸会变（#5）。
   - 两者都适合打斗、走位类镜头，对白特写仍以 H3 为主。

4. **后期改镜头**
   - Bernini-R（字节，Apache-2.0，Wan2.2-A14B 渲染器）：换装、局部修改、插入内容。
   - VOID（Netflix，Apache-2.0）：删掉物体，连同它和场景的互动一起删。
   - Capybara：按文字指令改视频，ComfyUI 模板使用量很低。
   - Wan VACE：遮罩局部重绘和外扩画面。
   - H3 Ref2VA 本身也能编辑视频，还能保留原音轨。
   - LTX-2.3 Dub-It：改台词，同时重新生成口型。
   - 闭源对照（来自训练记忆，未在 2026-10 复核）：Runway Aleph 能生成新机位、下一镜、重打光、增删物体；Kling O1 能用自然语言换主体、换背景、改风格，并支持多参考。

## 镜头类型 → 技术方案对照表

| 镜头 | 首选方案 | 备选/补救 | 要点 |
|---|---|---|---|
| **对话正反打** | 先用图像模型做好 A、B 两个机位的关键帧（在静帧阶段就保证 180° 轴线和视线方向一致），再分别用 H3 FL2VA I2V 生成；对白写 `(S1) says: <d>[Chinese]…</d>` | 15 秒内的短对话可以让 H3 一次生成多镜头：`[Shot 2] At 00:04.000, the camera cuts to…`，台词跨剪切用 `<scenetrans>`。LTX-2.5 多镜头最多放 2 个主体 | 每个角色的音色固定：用 Ref2VA 的 `<Audio N>` 做音色参考，或用 AddGuide 锚定音频。说话人编号在整集里保持不变 |
| **走位与调度** | 手机拍走位排练 → SDPose 提取骨骼 → H3 Fun ControlNet（strength 0.6–1.0）+ Ref2VA 的角色图 | Wan-Move 画轨迹（480p，之后超分）；运镜用 Wan2.2 Fun Camera；在 H3 里用 AddGuide 在关键节拍处钉住站位帧 | 控制视频的帧数对齐到 17k+5 |
| **打斗动作** | 真人或替身拍动作 → SCAIL-2（驱动或替换）或 Wan Animate 2；剪成 2–3 秒的短镜头 | 用 H3 Fun Pose 时调低 strength；后期超分用 ComfyUI 内置 SeedVR 节点或 LTX 像素超分 IC-LoRA | H3 的高动态会碎（#74），不要拿纯文本或 I2V 硬生成打斗 |
| **情绪特写（哭、怒）** | H3 I2V，关键帧里就已经带着泪痕或怒容；提示词写清楚抽泣、喘息等声音 | 真人演员的面部表演 → Wan Animate 2，按特写构图（参考图和驱动视频的取景要一致） | LTX-2.5 的扩散解码器宣称“脸更清晰”，可以对比测试 |
| **手部/道具特写** | 首尾帧生成（H3 FL2VA 或 LTX-2.5 FLF2V），首尾两帧都由图像模型生成 | 实拍手部动作 → Fun ControlNet 的 Depth/HED；手崩了用 Wan VACE 局部重绘 | 镜头控制在 3 秒以内，尽量单一动作 |
| **转场** | LTX-2.5 FLF2V（官方定位就是“过渡镜头、主体或场景变形”） | H3 首尾帧；提示词里可以明确要求 cross-dissolve、fade、wipe | 匹配剪辑：上一镜的尾帧直接当下一镜的首帧 |
| **空镜/建立镜头** | LTX-2.5 文生或图生视频（4K、HDR） | H3 文生视频；精确运镜用 Wan2.2 Fun Camera；预演用 FastH3 或 Causal Forcing | 空镜不需要口型，优先考虑画质 |
| **长镜头延续** | H3 AddGuide：上一段最后 22 帧加原声，`frame_idx` 设 0 | ComfyUI-H3-Motion-Context 节点；LTX 分块生成；Wan Animate 2 / SCAIL-2 分段串接 | 见“连续性技巧” |
| **多人同框** | H3 Ref2VA：每个角色 1–2 张图加场景图，在 `subject_definitions` 里逐一定义 | SCAIL-2 用彩色遮罩做多人替换；LTX-2.5 多主体最多 2 人 | 3 人以上容易串脸、说错台词 |
| **生成后修改** | 改台词：LTX-2.3 Dub-It。换装：Bernini-R 带参考图编辑。删路人或穿帮：VOID。局部重绘：Wan VACE 或 H3 Fun 遮罩 | 按文字指令改：Capybara。整段重编：H3 Ref2VA 视频编辑，原音轨可 1:1 保留。闭源：Aleph、Kling O1 | 编辑后用人脸相似度复检 |

## 真人表演驱动流程

**业内用得多不多**：没有拿到知乎、B 站的一手资料，普及程度未确认。旁证有两条：SCAIL-2 的 README 专门致谢了 B 站创作者（机智波、肥猴、绘篇AI手艺）的作品；Wan Animate、SCAIL 的模板在 ComfyUI 上有几百到上千次使用。从这些看，动作迁移主要用在舞蹈、打斗、走位这类镜头，对白镜头仍多用“关键帧 + 有声 I2V”。

1. **拍摄**
   - 手机竖屏，三脚架固定，均匀布光，背景越干净越好。
   - 取景景别要和目标镜头一致：Wan Animate 2 官方要求“全身对全身”。
   - 用领夹麦单独录干净的台词。
2. **切段**
   - Wan Animate 2：每段 81 帧（约 3.4 秒 @24fps）。
   - SCAIL-2：每段 76 帧，段间重叠 5 帧。
   - H3：最长 15 秒，帧数对齐到 17k+5。
3. **角色素材**：定妆照，景别与驱动视频一致；SCAIL-2 可以额外给背面、特写、背景参考。
4. **按需求选模型**
   - 保留实拍场景，只换人：SCAIL-2 替换模式，加重打光 LoRA，遮罩用 SAM3。
   - 换人同时换背景、换机位：Wan Animate 2。主提示词只写外貌和背景，第二个提示词写动作。
   - 想让画面和声音在同一个模型里一起出：SDPose 全身骨骼 → H3 Fun ControlNet + Ref2VA 角色图，台词音频作为 `<Audio>` 原样复用（`fully_copy`）或用 AddGuide 锚定。官方提示词指南支持这种写法，但“口型严格对上外部音频”的效果未实测，未确认。
5. **声音**：Wan Animate 2 和 SCAIL-2 输出的视频没有声音，需要另外合成音轨。
   - 演员原声先换成角色声音（变声工具不在本次调研范围），再和视频合轨。
   - 口型对不上时，用 InfiniteTalk（有 ComfyUI 模板）或 LTX Dub-It 重新做口型。
6. **拼接、超分、质检**：串接后用 SeedVR 超分；逐段用 insightface 测人脸相似度，参照 Wan Animate 2 #6 的做法，分数低的段重新生成。

## 连续性技巧

- **上一镜尾帧续写**
  - 简单做法：上一镜最后一帧当下一镜的 `first_frame`。
  - 推荐做法：取上一镜最后 22 帧加对应音频，接到 `MiniMaxH3AddGuide`，`frame_idx` 设 0。官方模板说明里写的就是“续写画面和声音两条流”，动作方向、速度和声音都能延续。
  - 需要的话再加 Ref2VA 的 `<Video 1>`，任务类型写成 `video continuation`。
- **首尾帧锁定落幅**
  - H3 FL2VA 两张图都接上，提示词第一行必须写参考图与时间轴的对应关系（“How the reference pictures align… 8.00-second mark”）。
  - FL2VA 更适合单镜头。
  - 注意：首帧会被直接拉伸到画布尺寸，尾帧是居中裁剪，所以两张图要先做成同样的 9:16 比例。
- **H3 MultiFrame 用法**
  - 一个 AddGuide 节点放一个关键帧，`frame_idx` 按 `round(秒数×24)` 计算，负数表示从结尾倒数，多个节点串联。
  - 关键帧位置加上片段长度不能超过总帧数。
  - 这些锚定图只在时间轴上起作用；如果想在提示词里用 `<Picture N>` 称呼它们，还要同时接进 `ref_images`。
  - 可以把一张静帧钉在中段（例如 124 帧里的第 60 帧），强制剧情在这一刻到位。
- **多参考保持服装和场景一致**
  - Ref2VA 最多 9 张图：角色正面、侧面、服装细节、场景各一张。
  - `ref_image_size` 设为 `max`（参考图按 2048 短边）时身份保真最好，但明显更慢。
  - 提示词按 `subject_definitions` / `retention_analysis` 结构写。
  - 其他工具：LTX-2.3 Ingredients 参考表；Bernini-R 换装（稳定约 5 张参考图）。
- **声音一致**：每个角色准备一段约 10 秒的干净音色参考，并固定说话人编号 (S1)、(S2)。
- **时长对齐**：H3 的帧数要对齐到 17k+5，例如 124 帧约 5.2 秒、243 帧约 10.1 秒、362 帧约 15.1 秒。

## 不确定项

- **调研范围**：WebSearch 只做了 6 次，额度耗尽；Reddit、知乎、B 站、arXiv、官方博客和文档都打不开。社区主观评价和中文对白实测都缺失。
- **AA 排名**：数字来自搜索摘要，各来源互相矛盾（编辑榜第 1 还是第 2），而且排名会变；LTX-2.5 的 AA 排名未查到。
- **H3 与海螺**：“H3 = Hailuo 3.0 开源版”只是社区说法。官方说开源的是 Base，Context-IR 和 2K 重生成没开源；H3 Max 由 fal 后训练闭源，这一点出自社区 awesome 列表。
- **H3 许可**：地域排除条款（欧盟/英国/韩国/美国）来自二手来源，需要读 HuggingFace 上的 LICENSE 原文。
- **中文对白**：H3 只有官方“稳定支持”的说法，没找到系统性的中文口型评测；LTX-2.5 的中文对白质量未确认；ID-LoRA 能否克隆中文音色未确认。
- **5090 性能数据**：均为社区自报，未复现。
- **其他权重许可**：Capybara、VOID（CogVideoX 底模）、SCAIL-2 权重、Causal Forcing 的许可均未确认。
- **口型对外部音频**：H3 用 AddGuide 或 `fully_copy` 锚定外部台词音频后，口型能否精确对上，是根据节点说明和提示词指南推断的，未实测。
- **Wan Animate 2**：v2 是否保留 v1 的“替换模式”（保留原背景）未确认；模板写的是“背景由文字生成”。
- **闭源产品**：Kling O1、Runway Aleph 的功能凭训练记忆，未在 2026-10 复核。
- **模板 `usage` 字段**：ComfyUI 模板里的使用量字段含义官方没写，只能当热度的粗略参考。
