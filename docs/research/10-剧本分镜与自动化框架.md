# AI 短剧框架、多镜头生成与 LLM 分镜：2026-10 调研报告

## 综述

**结论：** 到 2026-10，开源 AI 短剧生态分成了两条路线。

**路线一：一体化工作台。** 代表项目有 Toonflow（16.3k★）、火宝 huobao-drama（15.6k★）、waoowaoo（14.3k★）、ViMax（12.5k★）、DramaClaw（6.6k★）、Jellyfish（6.6k★）、ArcReel（5.3k★）。
- 它们的流程几乎一样：LLM 拆剧本 → 角色/场景/道具/服装资产库 → 分镜 → 首帧或参考图 → 视频 → TTS → 合成或导出剪映草稿。
- 主力生成大多走云 API（Seedance 2.0/2.5、MiniMax H3 API、GPT Image 2），本地 ComfyUI 只是可选接入。

**路线二：“Agent Skill + 文件即事实”。** 2026 年 7–8 月兴起，代表是 shuohao-skills（4.0k★）、drama-skills（2.4k★）和 MiniMax 官方的 `h3-prompt-writing` skill。
- 它们把分镜规范写成能用脚本逐条检查的“质量门”。
- 你们的 Python 编排器最该借鉴这一条路线。

**角色一致性的共同做法：** 先把演员和片场定下来再开拍。
- 资产：定妆照/三视图、衣橱变体、带光照状态的场景板、每一切（一次剪切）的冻结关键帧。
- 参考图按用途分工挂载：身份、构图、地理（空间布局）、造型各管一件事。
- 跨镜头不变的服饰写成一句能原样贴进提示词的“连续性锁”短语。
- 声音一致性靠每个角色固定的一段参考音频，用 H3 的 `<Audio N>` 做音色参考。

**多镜头：** 能落地的做法是“模型原生多镜头，每段 ≤15 秒，段与段之间续写”。
- H3：用 `[Shot k] At 00:0X.XXX` 时间轴，加 Add Guide 节点给每一切钉关键帧（ComfyUI 官方 multiframe 模板，2026-09-04 上线）。
- LTX-2.5：用散文写法、在文中点名转场的 native multishot。
- HoloCine、LongLive 2.0、Causal Forcing++、SVI 2.0 Pro、JoyAI-Echo 1.5 等研究项目，大多是非商用许可，或画质停留在 Wan2.1/2.2 那一代，只适合预演或长镜头空镜，不适合当真人对白主力。
- MoGA、LCT、Captain Cinema、MoC 目前没有可用的公开权重。

**关键风险：H3 只开源了一部分。**
- 开源的是 H3-Base：本地输出 768p，画布上限 768×1344。
- 官方原话说 H3-Context-IR 对质量“critical”，但它和 Regenerate-2K 都没开源。
- 所以你们必须自己做提示词的 IR（中间表示），可依据官方指南加 lightx2v 的 Prompt-Rewriter LoRA。2K 输出要么用 SeedVR2 超分，要么走付费 API。

**LLM：**
- 本地首选 2026-08 发布的 Qwen3.8-27B：稠密模型、带视觉塔，24 GB 卡就能跑，还能兼做质检。
- GPU 被 ComfyUI 占用时，把 Qwen3.6-35B-A3B（MoE）放到 128 GB 内存上跑。
- 云端只用来写一次性的创意初稿。

**自动质检：** 应该组合多种信号（ASR 逐字比对、ArcFace 人脸比对、OCR、切点检测、VLM 量表评分），再从多个候选里挑最好的（best-of-k），而不是只靠一个 VLM 打分。

> **证据局限：** 本次 WebSearch 只做成了 6 次，第 7 次就提示会话级 200 次额度已用完，所以没达到要求的 ≥20 次。arXiv、Reddit、知乎、B站、HuggingFace、ltx.io、minimaxi.com、docs.comfy.org、qwen.ai 都被出口代理屏蔽。因此证据主要来自 GitHub 上的原始文件：README、官方 ComfyUI 模板 JSON、官方 prompt guide 原文。

## 推荐的编排架构

### 1. 总体流水线

每个箭头都是一个可断点续跑的任务，每个产物都带版本和来源记录（prompt hash、seed、模型 hash）。

```
[0 Bible]      世界观/角色卡/场景卡/声音卡（LLM 起草 + 人审锁定）
  ↓
[1 Script]     分集剧本 = 场次 + 节拍流（动作/台词交替）；每拍秒数由“字数 ÷ 语速”确定性计算，不让 LLM 估
  ↓  validate（剧本质量门）
[2 Storyboard] 段（≤15 s，不跨场，换景必换段）→ 切（2–5 s，认领连续节拍）
               每切：景别/运镜（枚举）、起点 → 唯一动作 → 终点、对白、构图量化字段、参考槽位
  ↓  validate（约 18 道确定性门：覆盖、时长链、台词容量、同框 ≤3 人、运镜词表…）
     失败 → 把错误清单回喂 LLM 修复，最多循环 3 次
[3 Assets]     定妆照/三视图/衣橱 = Qwen Image 2.1 + Qwen-Image-Edit-2511
               场景板（按光照状态各一张）、道具板
               声音参考：每角色一条 5–10 s TTS 设计音
  ↓  QC：ArcFace 多角度一致性 + VLM
[4 Keyframes]  每切一张冻结首帧（Qwen Image 2.1，最多 10 张参考图），出 2–4 个候选 → VLM 选优（ViMax 式）
  ↓
[5 Compile]    确定性编译器（Python）：JSON → H3 IR（三字段/六字段）或 LTX 散文
               时间戳、对齐句、<Picture N> 编号、(Sx)、<d>、N/A 全部由代码生成
               LLM 只写每切的“镜头正文”
  ↓
[6 Generate]   ComfyUI API：H3 Ref2VA + 每切关键帧挂 Add Guide + <Audio N> 音色参考
               先用 turbo LoRA 出 K=2–3 个 seed 预览 → 选中的再用全步数出终版
  ↓
[7 QC]         L0 技术 → L1 切点 → L2 对白 ASR → L3 身份 ArcFace → L4 OCR → L5 VLM 量表
               → 决策：通过 / 换 seed / 打补丁改 prompt / 换模式 / 走口型修复 / 进人工队列
  ↓
[8 Post]       SeedVR2 超分到 1080×1920；InfiniteTalk 或 LatentSync 修口型
               字幕从剧本逐字取文本、用 ASR 对时间轴；响度统一
               FFmpeg 成片 / 导出剪映草稿
```

### 2. 按镜头类型选模型

| 镜头类型 | 首选 | 备选 / 修复 |
|---|---|---|
| 1–3 人对白中近景（段内 2–5 切） | **H3 Ref2VA + 每切关键帧 Add Guide + 角色音色 `<Audio N>`** | 逐切用 H3 FL2VA；口型错位时用 InfiniteTalk（V2V）或 LatentSync |
| 同场连续段（同一时空） | H3 续写：`<Video 1>` 放上一段**实际成片**，`<Picture 1>` 放它的实际尾帧，统一走 Ref2VA | MiniMaxH3-Easy 的 Context Segments（Motion Context，或要保音色时用 AV Prefix） |
| 无对白的建立镜、空镜、转场 | LTX-2.5（DFR I2V，或 2–4 切的 multishot） | H3 T2VA / I2VA |
| 复杂肢体表演（打戏、舞蹈） | Wan Animate 2：真人参考视频做动作迁移 | 降低动作强度后重写 |
| 单人长独白（超过 15 s） | TTS + InfiniteTalk | H3 分段 + AV Prefix |
| 字幕或乱码文字残留 | 重生成 | LTX-2.3 “Remove Subtitles” LoRA 官方模板 |

**对白音轨怎么处理（二选一，建议按项目开关）：**
- **(a) 保留 H3 原生同轨音频（推荐默认）。** 表演、呼吸、口型天然同步；音色靠 `<Audio N>` 参考，并用质检做声纹比对。
- **(b) 丢掉 H3 生成的语音，用 TTS + LatentSync 重配（4060 项目的做法）。** 音色 100% 可控，代价是表演感变弱、多一道口型修复。

### 3. 单卡 5090 的显存调度

H3 的官方 ComfyUI 文件：
- 扩散模型（pruned int8_convrot）19.53 GB
- 文本编码器（Qwen3-VL-32B NVFP4 AWQ）14.61 GB，Blackwell 原生支持 FP4
- 视频 VAE 2.62 GB，音频 VAE 0.58 GB

两个大件合起来约 34 GB，放不进 32 GB，只能分时加载。ComfyUI 0.30 起支持把权重放进锁页内存、按最近使用轮换（release notes 原文 “MRU policy using pinning”），128 GB 内存下切换代价可接受。

调度原则：
- **GPU 只给一个阶段用。** 按“驻留模型”批处理：一集的全部 H3 任务连续跑完 → 调用 ComfyUI `POST /free` 释放 → 加载 VLM 跑这一批质检 → 释放 → 进下一批。
- **LLM 常驻 CPU。** Qwen3.6-35B-A3B 放在内存里跑，与 ComfyUI 并行。
- **调大 LLM 只在 GPU 空闲时。** Ollama 用 `keep_alive: 0`；llama-server 按阶段启停。

**校验门（编译前必须全过）：**
1. 每个节拍恰好被一个切认领。

4. 一集总时长落在目标的 ±15% 内。

7. `<Picture N>` 编号与 ref_images 的接线顺序一致。
8. 运镜词来自官方词表。
9. 视频正文里不出现角色名（只用通用身份 / `<Subject N>`）。
10. 同框 ≤3 人。

### 5. 自动质检与重抽（全部本地）

| 层 | 工具 | 判定（起始阈值，需用你们自己的数据标定） | 失败后的动作 |
|---|---|---|---|
| L0 技术 | ffprobe；ffmpeg 的 blackdetect / freezedetect / silencedetect / ebur128 | 时长、fps、分辨率与计划一致；无黑场/冻帧；对白窗口内有声 | 换 seed |
| L1 切点 | PySceneDetect | 检测到的切点与计划差 ≤0.25 s，切数一致 | 补每切关键帧；把该段拆小 |

| L2b 口型归属 | SyncNet 类音画同步分（LatentSync 自带）+ VLM 问“t1–t2 谁的嘴在动” | 口型必须落在说话人脸上 | prompt 加 `X does not speak; his lips remain completely closed`；分镜上让不说话的人出画或背身 |

| L4 文字 | OCR（[GLM-OCR](https://github.com/zai-org/GLM-OCR) 或 PaddleOCR） | 只允许白名单里的画内文字 | 重生成，或走 LTX-2.3 去字幕 LoRA |
| L5 VLM 量表 | Qwen3.8-27B（视觉）或 Qwen3-VL-32B/8B（能直接看视频、带时间戳定位） | 输出 JSON 打分：手/肢体、面部融化、服饰与锁短语不符、道具变形、背景扭曲、构图与 spec 不符、情绪不符 | 把缺陷清单喂给 LLM 改写正文后重生成；评分很低就改模式 |
| 选优 | VLM 两两比较（ViMax 式 best-of-k） | 在已通过的 take 里选最好的 | — |

- 每段最多重抽 3 次，仍不过就进人工队列。
- 每道门的命中记录写入 `.gates.jsonl`（shuohao 的做法），定期统计哪条规则最常被模型违反，用来改提示词措辞。

## 提示词模板与规则

### A. MiniMax H3 官方规则摘录

**来源：**
- [`skills/h3-prompt-writing/references/base-en.txt`](https://github.com/MiniMax-AI/MiniMax-H3/blob/main/skills/h3-prompt-writing/references/base-en.txt)
- [`ref-en.txt`](https://github.com/MiniMax-AI/MiniMax-H3/blob/main/skills/h3-prompt-writing/references/ref-en.txt)
- [README](https://github.com/MiniMax-AI/MiniMax-H3)
- 两份全文我已下载到：`<调研时的本地缓存>` 和 `h3_ref-en.txt`，可直接嵌进编译器。

**1. 结构。** T2VA / I2VA / FL2VA / L2VA 用三个字段：`integrated_multimodal_description`、`overall_soundscape`、`non_diegetic_music`。
- I2VA 第一行固定写：`For the target video, at 0.00 seconds into the target video, <Picture 1> (from [Shot 1]) is fully referenced.`
- FL2VA 第一行固定写：`How the reference pictures align with the target video — Picture 1 (from Shot 1) aligns with the 0.00-second mark …; Picture 2 (from Shot N) aligns with the S.SS-second mark …`（S.SS 精确到两位小数）。
- 第一行之后空一行，再写三个字段。

**2. 切镜。** 原文：“Do not add a timestamp to the first shot… begin each one with a strictly increasing cut time that falls within the video duration”，写法如 `[Shot 2] At 00:03.500, the camera cuts to…`。
- 原文：“If only the distance or a slight angle needs to change, prefer camera motion.” 只是景别或角度微调时，用运镜，不要切。
- FL2VA “generally favors a single shot”，首尾帧模式尽量单镜。

**3. 运镜 = 类型 + 幅度 + 速度。**
- 类型词表：Zoom In/Out、Push In / Pull Out、Pan、Truck、Tilt、Pedestal、Arc Shot、Tracking Shot、Static Shot、Shake Slightly/Strongly、POV、Roll。
- 幅度：`with small/large amplitude`；速度：`at slow/fast speed`；中等幅度、正常速度可省略。
- 必须写成镜头里自然的英文动作句，例如 “The camera pushes in with small amplitude at slow speed toward…”，不要把标签堆在句尾。

**4. 说话人与对白。**
- 说话人用稳定 ID `(S1)`、`(S2)`，跨镜不变；合唱或齐声用 `(S1,S2)`；不出声的角色不给 ID。
- 原文：“Place the speaker's identifying phrase, ID, action, and delivery outside `<d>`. Inside `<d>`, include only the language tag and the actual user-provided spoken content. Preserve every original word and punctuation mark verbatim”。
- 中文写成 `<d>[Chinese] 原文</d>`。
- 画外音必须用固定短语 `says in an off-screen voiceover`，并紧接着写说话人的嘴唇保持闭合（`while his lips remain completely closed`）。
- 一句台词跨切时，两侧都用 `<scenetrans>`；被片尾截断时用 `<cutoff>`。

**5. 画面里的文字。** 招牌、字幕条等真实可见的文字，用英文双引号原样写，不翻译，例如 `A red neon sign reading "营业中"`。

**6. 声景与配乐。**
- `overall_soundscape`：1–4 句英文，写环境声、动作声、非语言人声，不重复对白。
- `non_diegetic_music`：1–3 句英文，写配器、速度、动态，原文 “do not use abstract mood words”；没有配乐就写 `N/A`。

**7. Ref2VA（全参考模式）。**
- 六段：`subject_definitions`、`summary`（以 `[reference generation + …]` 这类任务类型前缀开头）、`retention_analysis`、`detailed_description`、`overall_soundscape`、`non_diegetic_music`。
- 原文：“Write all six rewrite sections in English. Preserve the original language only for dialogue and lyrics inside `<d>`”。
- `detailed_description` 在 `[Shot 1]` 之前用一两句交代风格；生成任务一般写 **350–500 个英文词**。
- 保留强度标记：画面用 `fully_preserved / partially_preserved / attribute_transfer / weak_reference`；音频用 `fully_copy / partially_copy / reference / weak_reference`。
- 说话的参考主体写成 `<Subject N> (Sx)`；`<Audio N>` 作为音色参考时写 `<Audio 1> is the voice-timbre reference for <Subject 1> (S1).`

**8. README 原文：** “H3-Context-IR is critical to the quality of the final output … strongly recommend … following the ‘Prompting Guidance’ to build your own context-processing system.” 支持中文在内的 11 种对白语言；输出 4–15 s、24 fps、32 kHz 立体声。

**9. ComfyUI 官方模板注释**（[r2v](https://github.com/Comfy-Org/workflow_templates/blob/main/templates/video_minimax_h3_r2v.json) / [multiframe](https://github.com/Comfy-Org/workflow_templates/blob/main/templates/video_minimax_h3_multiframe_reference.json)）：
- 原文：“Ref2va's output is very sensitive to prompt wording; matching the reference tags precisely and being explicit about which reference drives which part of the shot tends to work best”。
- 身份要求高时设 `ref_image_size: max`（最长保留到 2048 短边，速度更慢）。
- 采样器用 `res_multistep`；参考图多时 `beta` 或 `normal` 调度器优于 `simple`。
- 原生画布短边 768，上限 768×1344；帧数取 **17k+5**（24 fps），例如约 5 s 取 124 帧，9 s 取 226 帧。
- `<Picture N>` 只绑定真正接在 ref_images 上的图片；Add Guide 节点按 `frame_idx = round(秒数×24)` 钉帧。
- 模板原文说 Lightning LoRA “fast … but scarce video quality”，只用于预览。

**10. 关于 “Timeline [0s-1s]” 写法。** 官方 ComfyUI 的 [i2v_continuation 模板](https://github.com/Comfy-Org/workflow_templates/blob/main/templates/video_minimax_h3_i2v_continuation.json) 示例 prompt 用的是 `Timeline: [0s-1s] … [1s-2.5s] Hard cut…` 加 `Audio:` 加禁止项（“no subtitle bars”）的口语化写法。但 MiniMax 官方 IR 是上面的 `[Shot k] At MM:SS.mmm` 三字段结构。**建议：** 人写的草稿可以用 Timeline 写法，进模型前一律由编译器转成官方 IR。

### B. 实测经验规则（drama-skills [minimax-h3.md](https://github.com/zenstory-ai/drama-skills/blob/main/skills/short-drama-video-prompts/references/minimax-h3.md) 小样本，非官方）

- **每切都挂关键帧，切点才准。** 一段 9 s 三切（要求 3.0 / 6.0 s 切），每切挂关键帧时，实际切点落在 2.88–3.04 / 6.00–6.04 s，生成次数只有逐镜生成的 1/3。只挂第一切关键帧时，切点漂到 2.92–3.88 / 5.88–6.21 s，第 2、3 切构图明显偏离，还多出过一切。**没有逐切关键帧就不要把几切装进一段。**
- **只挂场景图时要写具体取景。** 只写 “Medium shot” 加场景图，8 次里出了远景 3、中远景 3、中景 2。改写成“画面下沿切在腰部、主体占画面多高、头顶在哪一段、机位高度”后，8 次里中景 7、中远景 1。
- **口型会落到最显眼的正脸上。** 台词期间画里有别人的正脸时，明写 `X does not speak; his lips remain completely closed.`：3 次里口型落对从 2 次升到 3 次。
- **没配乐要明写 `N/A`。** 省略这一字段时出现过多余的配乐。
- **互斥输入。** 首尾帧模式和 reference 输入在同一请求里互斥。所以“起始帧 + 角色板 + 场景板”要整组走 Ref2VA，起始帧也作为 reference_image 送入。续写时：上一段实际视频作 `<Video 1>`，它的实际尾帧作 `<Picture 1>`。
- **中文语速。** 小样本约 4.1 个可发声字/秒，出现过赶词和静默截断；不要把逐字秒数硬塞进 prompt。
- **全英文还是全中文。** shuohao 支持整条用中文写，但它自己也注明“偏离官方推荐…实测中文效果不稳就回英文”。

### C. H3 编译模板：一段 9 s、三切、中文对白（Ref2VA + 多关键帧）

**ComfyUI 接线：**
- ref_images 按顺序接：kf1, kf2, kf3, C01 设定图, C02 设定图, S01 场景板（对应 Picture 1–6）。
- 两个 Add Guide：kf2 放 frame 72（3.0 s），kf3 放 frame 144（6.0 s）。
- ref_audios 接 C01 和 C02 的音色参考。
- 帧数 length = 226。

```text
subject_definitions:
<Subject 1> is the young woman in <Picture 4>, mid-20s, slender, with a low black ponytail, wearing an ivory silk blouse with a thin black ribbon tie and small pearl earrings.
<Subject 2> is the man in <Picture 5>, early 30s, short side-parted black hair, wearing a charcoal three-piece suit and a silver wristwatch.
<Subject 3> is the CEO office in <Picture 6>, with a floor-to-ceiling window showing night city lights on the left wall, a dark walnut desk and a warm brass desk lamp.
<Picture 1> is the first frame of [Shot 1]. <Picture 2> is the keyframe of [Shot 2]. <Picture 3> is the keyframe of [Shot 3].
<Audio 1> is the voice-timbre reference for <Subject 1> (S1).
<Audio 2> is the voice-timbre reference for <Subject 2> (S2).

summary:
[keyframe completion + reference generation + audio reference] In <Subject 3> at night, <Subject 2> questions <Subject 1> across the desk, she answers coldly, and the scene ends on his tightening reaction, following <Picture 1>, <Picture 2> and <Picture 3> as cut anchors.

retention_analysis:
<Picture 1> ([Shot 1] first frame): fully_preserved - waist-up two-shot framing, his seat behind the desk on frame left, her standing position on frame right.
<Picture 2> ([Shot 2] keyframe): fully_preserved - close-up framing and head angle of the woman.
<Picture 3> ([Shot 3] keyframe): fully_preserved - medium close-up framing of the man.
<Subject 1> (appears in [Shot 1], [Shot 2]): fully_preserved - face shape, ponytail, ivory silk blouse with thin black ribbon tie; pose and expression are set by each shot, not by <Picture 4>.
<Subject 2> (appears in [Shot 1], [Shot 3]): fully_preserved - face shape, side-parted hair, charcoal three-piece suit, silver wristwatch.
<Subject 3> (appears in [Shot 1], [Shot 2], [Shot 3]): partially_preserved - window wall, walnut desk and lamp positions are kept; framing comes from the keyframes.
<Audio 1>: reference - only voice timbre and measured delivery are followed; no original words are reused.
<Audio 2>: reference - only voice timbre and calm husky delivery are followed.

detailed_description:
The target video is live-action, cinematic, vertical 9:16, with low-key warm practical light from the desk lamp and cool blue city light through the window.
[Shot 1] The shot begins from <Picture 1>: a medium two-shot with the frame's bottom edge at waist height. <Subject 2> sits behind the walnut desk on frame left; <Subject 1> stands on frame right about one step from the desk edge, the two facing each other in profile. ```
```

**台词容量检查：** “你还回来干什么？”7 字约 2.0 s，“拿回属于我的东西。”8 字约 2.3 s，都能放进 3 s 的切。**单切 I2VA** 版本：把第一行换成官方 I2VA 固定句，主体字段换成 `integrated_multimodal_description: [Shot 1] Live-action, cinematic, …` 即可。

### D. LTX-2.5 规则与模板

**官方规则（[LTX-2 README](https://github.com/Lightricks/LTX-2) 的 “Prompting for LTX-2”）：**
- 原文：“focus on detailed, chronological descriptions… all in a single flowing paragraph. Start directly with the action, and keep descriptions literal and precise. Think like a cinematographer… Keep within 200 words.”
- 推荐顺序：主动作一句 → 动作和手势细节 → 外貌 → 环境 → 机位和运镜 → 光与色 → 变化或突发事件。

**官方 ComfyUI 模板注释（2026-08-11）：**
- Native multishot 原文 “holding character, environment, lighting, voice, and style across cuts”。
- Gemma 4 12B 编码器能保留多主体、动作、光线、机位信息。
- 可选的 Prompt Enhancer 约 10 GB，每次多 1–2 分钟。
- 有 Auto Duration；DFR 默认 1024×1536（竖幅）。
- 尺寸用 32 的倍数；帧数 `8k+1`。

**多镜头写法（社区 [LTX-2.5-Agent-Prompt-Skill](https://github.com/benjiyaya/LTX-2.5-Agent-Prompt-Skill) 和 runware/deAPI 指南的搜索摘要，原文页被屏蔽，未逐字核实）：**
- 一次生成 2–4 切。
- 全部写在一个按时间顺序的段落里，不用 Shot 1 / 编号列表。
- 每个切点用自然语言点名转场（“A hard cut transitions to…”）。
- 每切重新交代景别和机位，复用同一句外貌标签。
- 写明声音如何跨切（“the room tone continues across the cut”）。
- 每切只有一个主动作；情绪写成身体细节，不写抽象情绪词。

**模板（适合无对白或少对白的 B-roll；LTX 的中文对白能力未确认）：**

```text
Live-action vertical 9:16 drama, night office lit by a warm brass desk lamp and cool blue city light through a floor-to-ceiling window. A medium two-shot framed at waist height shows a man in his early 30s with short side-parted black hair and a charcoal three-piece suit seated behind a dark walnut desk on the left, and a slender woman in her mid-20s with a low black ponytail and an ivory silk blouse with a thin black ribbon tie standing on the right; the camera is static as the man leans back and his leather chair creaks. A hard cut transitions to a close-up of the woman in the ivory blouse; the camera slowly pushes in as she lifts her chin and her fingers tighten on her bag strap. The view cuts to a medium close-up of the man in the charcoal suit, his jaw tightening as he exhales through his nose, his hand flattening on the desk. The low air-conditioning hum and muffled city traffic continue across every cut; no music, no subtitles, no on-screen text.
```

### E. Qwen Image 2.1 / Edit 2511：关键帧与定妆

**官方规则（[Qwen-Image-2.1 README](https://github.com/QwenLM/Qwen-Image-2.1) 与 ComfyUI 模板）：**
- 官方推荐先用 prompt 改写模型：Qwen-Image-2.1-PE-T2I / PE-I2I，是微调过的 Qwen3.5-VL 9B。它把短 prompt 扩写成“long detailed English prompt”，并输出 `wh_ratio` 画幅。ComfyUI 模板里内置为 `qwen3.5_9b_qwen_image_2.1_pe_t2i.int8_convrot`，开关叫 `refine_prompt`。
- 编辑时输入图片排在文字前面，最多 10 张参考图，“preserve identity for people and products”。
- 原生 2K：9:16 推荐 1536×2752；默认 40 步。
- 透明图固定句式：`This is an RGBA image with transparency. … The image has alpha channel and the background is transparent.`

**关键帧模板（英文，用图片编号引用，不写画风长句，画风由全局后缀统一附加）：**

```text
Vertical 9:16 live-action film still, medium two-shot framed from the waist up at eye level, 50mm lens, medium-shallow depth of field.
The man from image 1 (keep his face, side-parted black hair and charcoal three-piece suit exactly) sits behind a dark walnut desk on frame left, leaning back, looking at the woman.
The woman from image 2 (keep her face, low black ponytail, ivory silk blouse with a thin black ribbon tie) stands on frame right one step from the desk edge, gripping her bag strap, chin slightly lowered, eyes on him.
Setting is the office from image 3 (keep the window wall on the left, the walnut desk and the brass lamp position).
Warm lamp key light from frame left, cool blue city light rimming both figures.
No text, no subtitles, no watermark, no logo.
```

**定妆照：** 白底或灰底，正面全身做锚点 → 用 Edit 2511 衍生 3/4 侧、90° 侧面、背面、头像特写 → 衣橱变体都从基础形象图编辑出来（换衣不换脸）→ 每一张都进 ArcFace 库。

### F. 剧本 → 分镜的 LLM 系统提示词（中文骨架）

```text
你是竖屏真人短剧的分镜导演。输入：本集剧本（场次+节拍，每拍已给秒数和说话人）、角色卡、场景卡。
输出：严格符合给定 JSON Schema 的 segments，不要任何解释文字。

硬规则：
1. 段 = 一次视频生成，9–15 秒，不跨场次；换景必开新段。
2. 段内切镜，每切 2–5 秒，以 3 秒为基准；每切用 beats:[起,止] 认领连续节拍；全场节拍不重不漏、按顺序。
3. 台词逐字照抄剧本，一个标点都不改；每切台词按 3.5 字/秒计算，必须 ≤ 该切秒数 − 0.5。
4. 每切只有一个主运镜（只能从给定枚举里选），只有一个主动作；必须写清 起点 → 唯一动作 → 终点，且终点就是下一切的起点。
5. 情绪写成身体细节（握紧、下颌绷紧、视线躲闪），禁止“悲伤/愤怒”这类抽象词；动作要能在该切秒数内完成，避免精细手指动作和剧烈运动。
6. 镜头正文 shot_en 用英文通用身份（a slender woman in her mid-20s …），不写角色名；角色名只出现在 dialogue.text 里。
7. 每切填齐 size/lens/framing/eyeline/stability；每段写 blocking（谁在左、谁在右、朝向、相距几步）。
8. 对话按正反打切；重台词后给 2–3 秒听者反应镜；每集第一切必须有运动主体；每段最后一切留钩子。
9. 同框不超过 3 人；台词期间画面里有其他正脸时，把他列进 silent_onscreen。
10. 不新增剧本里没有的人物、道具、台词或可见文字；不写画风词。
声音分三层：台词进 dialogue；环境声/动作声进 soundscape_en（1–4 句）；配乐进 music_en，没有就写 "N/A"。
```

**落地方式：**
- 用 Pydantic 定义 schema，开启约束解码：llama-server 或 vLLM 的 `response_format: json_schema`。
- 生成后跑校验门，把错误清单原样回喂 LLM 修复，最多 3 轮。
- 时间戳、对齐句、`<Picture N>` 编号一律由 Python 编译器生成，不让 LLM 写。

**命令 ①：Qwen3.8-27B 主力（llama.cpp，带 MTP 投机解码 +33% 以上，来自 qwen38-mtp）**

```bash
llama-server -m Qwen3.8-27B-UD-Q5_K_XL.gguf --mmproj mmproj-BF16.gguf \
  -c 65536 -ngl 999 -fa 1 --cache-type-k q8_0 --cache-type-v q8_0 \
  --spec-type draft-mtp --spec-draft-n-max 2 --parallel 1 --jinja --port 8081
```

- GGUF 来自 unsloth/Qwen3.8-27B-GGUF；视觉投影（mmproj）文件名未确认，以 HuggingFace 页面为准。
- 参考速度：4090 从 47.7 提到 76.3 tok/s，移动版 5090 从 36.7 提到 50.9 tok/s（README 实测表）；桌面 5090 无数据。
- **vLLM 备选：** [HyperQwen](https://github.com/syv-ai/HyperQwen) 一条命令 `docker compose --profile single up -d`，24 GB 卡单流 127 tok/s（3090 实测），64 并发批处理约 1035 tok/s，适合批量编译 prompt 和质检。

**命令 ②：Qwen3.6-35B-A3B 纯 CPU**

```bash
llama-server -m Qwen3.6-35B-A3B-Q8_0.gguf -ngl 0 -t 16 -c 32768 --jinja --port 8082
```

- GPU 空闲时可改成 `-ngl 999 --n-cpu-moe 30`，让部分专家层留在 CPU。

**其它要点：**
- **Ollama：** 请求里设 `"keep_alive": 0`，或设环境变量 `OLLAMA_KEEP_ALIVE=0`，调用后立即释放显存，方便与 ComfyUI 共用 GPU。模型 tag（例如 `qwen3.8:27b`）未确认。
- **结构化输出：** 一律用 `response_format: {"type":"json_schema", …}`，配合 Pydantic 校验和修复循环。
- **云端怎么用（价格未确认，相关页面被屏蔽）：** 剧本大纲、分集、人物小传这类低频创意稿，可用 Claude、DeepSeek V4、Qwen3.8-Max（QwenCloud 兼容 OpenAI/Anthropic 协议）或 GPT。一整部剧也就几百万 token，相比视频生成成本可以忽略。高频的 prompt 编译和质检循环放本地。
- **视频生成 API 价格参考：** 第三方 H3 转售价 768P ¥0.09/秒、2K ¥0.15/秒（[ArcReel](https://github.com/ArcReel/ArcReel) README 中的赞助商广告，未独立核实）。可用于主角镜头的 2K 混合方案。

## 不确定项

1. **检索受限。** WebSearch 只做成 6 次（第 7 次提示会话级 200 次额度已满），未达到要求的 ≥20 次。arXiv、Reddit、知乎、B站、HuggingFace、ltx.io、minimaxi.com、docs.comfy.org、qwen.ai、runware、deapi 都被出口代理屏蔽。社区实测口碑（Reddit、B站）基本缺失，LTX-2.5 官方 prompt guide 原文没能读到（只拿到搜索摘要和社区 skill）。
2. **H3 本地画质 vs API 画质：** 本地没有 Context-IR，自建 IR（官方指南或 lightx2v LoRA）能接近到什么程度，未确认。本地 2K 只能靠 SeedVR2 或 latent upscaler，效果与 Regenerate-2K 的差距未确认。
3. **桌面 RTX 5090 跑 H3 的耗时：** 只有 4060 移动版 8 GB 的数据（0.98MP、20 步、5 s 约 53 分钟；turbo 0.3MP、8 步约 7 分钟）。5090 上 768×1344、15 s 一段的耗时未确认；**我的估算**是全步数每段几十分钟，需要实测后再定 K 值和 turbo 策略。
4. **LTX-2.5：** 中文普通话对白和口型质量、multishot 的实际切镜准确度、9:16 下的表现，都没有找到第三方对比（未确认）。
5. **shuohao 的多图对齐句与官方接口是否吻合：** shuohao-skills 用多张 Picture 的对齐句（FL2VA 式）对齐多切；而官方 FL2VA checkpoint 只支持 0–2 张图。多关键帧建议按 ComfyUI 官方做法走 Ref2VA + Add Guide。shuohao 的写法能否被官方接口正确解析，未确认。
6. **“视频正文禁止写角色名”不是官方原文。** 这是 shuohao 和 drama-skills 的说法。官方指南的示例确实只用视觉身份或 `<Subject N>`，但我没找到明文禁令。
7. **Timeline `[0s-1s]` 写法的效果：** 它出现在 ComfyUI 官方续写模板的示例里，和官方 IR 写法相比效果孰优，未确认。
8. **模型细节：** Qwen3.8-27B 的 mmproj 文件名、Ollama tag、各量化档的确切体积；Qwen3.8-Flash-Next 在 llama.cpp 上的速度；Gemma 4 的具体规格；DeepSeek V4 的参数量和价格，均未确认。
9. **MoGA、LCT、Captain Cinema、Mixture of Contexts：** 只确认 GitHub 上没有可用权重；论文的后续版本未能查证。
10. **数字的来源与精度：** star 数是 2026-10-02 的 GitHub 搜索快照；“活跃”根据 README 新闻判断。drama-skills 的 H3 实测都是小样本（2–19 次），只能当方向参考。质检阈值（ArcFace 0.40–0.50、CER 5% / 15%、切点 ±0.25 s）是建议的起始值，需要用你们的数据标定。
11. **ComfyUI 版本：** v0.38.0 于 2026-09-29 发布（GitHub releases 页面，摘要工具把年份显示成了 2024，我判断是解析错误）。
