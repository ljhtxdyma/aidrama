# 08-后期超分插帧合成

> 原始调研笔记（2026-10-02，云端调研时整理）。正文结论已汇总进 docs/01-调研报告.md；这里保留细节与出处，标“未确认”的地方没有独立核实。

## 综述

**说明：**本次只完成了 16 次 WebSearch，少于要求的 20 次。原因是会话级检索额度（200 次）已用完。另外，代理拦截了 cac.gov.cn、gov.cn、openstd、docs.comfy.org、知乎、B站等站点。所以大部分关键事实改为直接读 GitHub/PyPI 上的源码、官方 README、ComfyUI 官方模板 JSON 来核验。国标全文取自 GitHub 上的公开文本镜像。

**1. 超分**
- **ComfyUI 原生化已完成。** SeedVR2 原生支持来自 PR #14424，2026-07-10 合并，v0.28 起可用，模型为 Comfy-Org 重打包的 3B/7B int8 convrot。0.38（2026-09-29）合入 PR #16530：VAE 改为逐帧处理，因果卷积缓存以 int8 放在锁页内存（pinned host memory），显存占用降到"一帧的工作集"。
- **原生补帧与调色节点。** `FrameInterpolate` 支持 RIFE 4.25/4.26 和 FILM，2026-04-22 合入。原生 `ColorTransfer` 支持 reinhard_lab / mkl_lab / histogram 三种方法，统计方式有 per_frame / uniform / target_frame。VOID（Netflix 的视频物体移除模型）+ SAM3.1 也已有官方模板。后期链路几乎可以全部用原生节点完成。
- **SeedVR2 仍是 AI 视频超分开源首选，但人脸有风险。** 它是 ICLR 2026 论文，Apache-2.0。官方 README 原话："tend to overly generate details on inputs with very light degradations, e.g., 720p AIGC videos, leading to oversharpened results"。对真人风短剧来说，主要风险是皮肤塑料感、眼睛/牙齿细节被重写；整体脸型变形较少。对策：
  - 颜色校正用 lab；
  - 与 Lanczos 放大的原图做 20–35% 混合，或在输入端加微量噪声；
  - 特写镜头用 7B，不用 sharp 变体。
- **其他超分方案定位：**
  - FlashVSR v1.1（CVPR 2026）快约 11.8 倍，但只为 4× 设计，和 768×1344→1080×1920（约 1.43×）的需求不匹配。
  - NVIDIA RTX VSR 原生节点不是扩散模型，秒级、不改脸，适合远景、预览和兜底。
  - InfVSR（ICML 2026）今天（10-02）刚放出权重，尚未验证。
- **耗时是主要瓶颈（估算）。** 每分钟成片，3B 约 20–40 分钟，7B 约 40–80 分钟。所以必须"先锁定剪辑再超分"，并按镜头分级处理。

**2. 补帧**
- 不建议把 24fps 补到 60fps。60fps 会有"肥皂剧感"，并放大 AI 瑕疵。短剧平台 24/25/30fps 都能接受；红果 AI 漫剧据第三方文章要求 24fps。
- 只有模型原生输出 16fps 时才需要补帧：做法是 ×3 到 48fps，再抽帧到 24fps，时间点完全精确。
- RIFE 4.25 是作者推荐的默认版本，作者也说 4.24+ 适合扩散模型生成的视频。FILM 适合大幅运动。GIMM-VFI 是 S-Lab 非商用许可，商业短剧不能用。

**3. 色彩与颗粒**
- 用 `ColorTransfer(mkl_lab, uniform)` 把每个镜头对齐到场景参考帧，再套全片 LUT。
- 颗粒只加亮度噪声，用 ffmpeg 的 `noise=c0s`。
- 逐帧人脸修复（CodeFormer 非商用、GFPGAN）会闪烁、导致身份漂移，不推荐。

**4. 字幕**
台词在剧本里是已知的，应该做"强制对齐"而不是语音识别。首选 Qwen3-ForcedAligner-0.6B（2026-01-29，Apache-2.0，可输出字级时间戳）。用 pysubs2 生成 ASS，再通过 libass 烧录进画面。

**5. 剪辑交接**
- ffmpeg 自动拼出一版"参考成片"。
- 给达芬奇：生成 OTIO / FCP XML。
- 给剪映：用 pyJianYingDraft 0.3.0（2026-07）生成草稿。剪映 10.8 能打开，但 7.0 以上版本的自动导出不可用，只能人工导出。

**6. 合规**
- 显式标识：文字必须包含"AI/人工智能"和"生成/合成"，放在起始画面的边或角，字高不低于最短边的 5%（1080 宽即 ≥54px），持续不少于 2 秒。
- 隐式标识：元数据里写入 AIGC 七要素 JSON。MP4 可以用 ffmpeg `use_metadata_tags` 写入 `moov/udta/meta keys(AIGC)+ilst`。
- 发布时必须主动声明，不得删除或篡改标识。所以不能用 VOID 去掉 API 生成视频上的水印或标识。
- 广电总局 2026 年针对 AI 微短剧的专项新规：**未能核实**。

## 推荐后期链路

总体原则：
- **先锁剪辑，再超分。** 拿 RTX VSR 的快速版本去剪，定剪后只对用到的帧段（每头尾各留 8–12 帧余量）跑 SeedVR2。
- **按镜头处理。** 镜头切点就是分块边界，可以避免跨镜头的时间伪影。

耗时均为每分钟成片的估算，5090 未实测。

| 3 | 超分 | 原生 SeedVR2：人脸近景、特写用 7B int8，其余用 3B int8 | 远景和预览用 RTX VSR ULTRA；需要更细控制时用 numz 7B fp16 | 对 AI 素材效果最好；0.38 显存进一步优化 | 见下方参数清单 | 3B 20–40 分钟 / 7B 40–80 分钟；RTX VSR 1–2 分钟 |
| 4 | 色彩一致 | 原生 ColorTransfer 对齐场景参考帧 → 全片 LUT（ffmpeg `lut3d` 或达芬奇） | 达芬奇 Shot Match | 不同镜头之间色温、对比度会漂移 | `method=mkl_lab`，`source_stats=uniform`，`strength 0.5–0.8`；不要用 per_frame（会闪） | 1–3 分钟 |
| 5 | 去闪 / 颗粒 | ffmpeg `deflicker=size=5:mode=pm`（只在亮度忽明忽暗时用）+ 只加亮度颗粒 `noise=c0s=3:c0f=t` | 达芬奇 Studio 的 Deflicker | 统一质感，掩盖色带；平台转码会抹掉过重的颗粒 | 颗粒强度 2–4 | 实时级 |
| 6 | 混音与响度 | 对白分轨 → BGM 用 `sidechaincompress` 闪避 → `loudnorm` 两遍法 | 达芬奇 Fairlight | 可完全自动化 | 目标 -16 LUFS，真峰值 ≤ -1.5 dBTP，LRA 11（经验值） | 1 分钟 |
| 7 | 字幕 | 台词稿 + Qwen3-ForcedAligner → pysubs2 生成 ASS → libass 烧录 | FireRedASR2 识别 / WhisperX | 台词已知，对齐比识别更准 | 每行不超过 12 字、单行、0.8–6 秒；去掉句末标点，句中逗号换成空格 | 秒级 |
| 8 | AI 标识 | ASS 常驻角标 + ffmpeg 写 AIGC 元数据 | drawtext 滤镜 | 满足 GB 45438 第 5.4 条和第 6.1 条 | 字号 ≥64（字形高度 ≥54px）；最终封装时写元数据 | 0 |
| 9 | 时间线交接 | ffmpeg 出参考成片 + OTIO / FCP7 XML（达芬奇）+ pyJianYingDraft 草稿（剪映） | VectCutAPI | 自动化粗剪，人工精修 | 交付包：每镜头素材、对白/BGM/音效分轨、SRT 与 ASS、.otio、剪映草稿 | 1 分钟 |
| 10 | 成片编码 | x264 High，CRF 16–17，maxrate 20M | 两遍 VBR，目标 12M | 平台会二次转码，原片高码率更好 | 1080×1920、源帧率、AAC 48kHz 256k、+faststart | 1–2 分钟 |

**SeedVR2 原生参数清单（第 3 步）：**
1. **先缩放。** 720×1280 源用 ×1.5，正好得到 1080×1920。768×1344 源比例是 4:7，不是 9:16：先按 ×1.4286（1920/1344）放大到约 1097×1920，再居中裁到 1080。缩放用 lanczos。
2. **采样。** KSampler 用 steps 1、cfg 1.0、euler、simple、denoise 1.0，这是官方模板值。
3. **分块。** `SeedVR2TemporalChunk` 选 auto。一个镜头被切成多块时，`temporal_overlap` 设 1–2 个 latent 帧（相当于 4–8 个像素帧）。手动模式下帧数必须是 4n+1。
4. **VAE。** VAEEncodeTiled / VAEDecodeTiled 用模板值 512 / 128 / 64 / 8。
5. **调色。** `SeedVR2PostProcessing` 选 `lab`。注意官方模板默认是 `none`，需要手动改。
6. **防过锐（经验值）。** 两种做法：
   - 输出后用 `ImageBlend`（normal 模式），与 Lanczos 底图混合，blend_factor 0.2–0.35；
   - 或在输入端加 `ImageAddNoise`，strength 0.01–0.03。
   - numz 节点对应参数：`input_noise_scale` 0.1–0.3，`latent_noise_scale` 0.05–0.15。
7. **模型选择。** 不要用 7B sharp 变体处理皮肤。
8. **帧率连线。** CreateVideo 的 fps 要连到 GetVideoComponents 的帧率输出，否则会变速。

多段 xfade 的 offset 生成器（第 i 次转场的 offset = 前面各段时长之和 − i×d）：
```python
def xfade_graph(durs, d=0.5, t="fade"):
    g, prev, off = [], "[0:v]", 0.0
    for i in range(1, len(durs)):
        off += durs[i-1] - d
        g.append(f"{prev}[{i}:v]xfade=transition={t}:duration={d}:offset={off:.3f}[x{i}]")
        prev = f"[x{i}]"
    return ";".join(g), prev
```

## 合规要求清单（带出处）

1. **施行时间与性质。** 《人工智能生成合成内容标识办法》（国信办通字〔2025〕2号）自 2025-09-01 施行（第十四条）。GB 45438—2025 是强制性国标，2025-02-28 发布，2025-09-01 实施。
   出处：[CAC 原文](https://www.cac.gov.cn/2025-03/14/c_1743837673293647.htm)、[openstd](https://openstd.samr.gov.cn/bzgk/gb/newGbInfo?hcno=38E3BFDE20AE4A53B8A8BD52BE8F3B9F)、[全文镜像](https://github.com/Coase-lawfirm/ai-labeling-compliance)。

2. **你方的身份与义务。** 在本地用开源模型自制、再到平台发布，主要承担"用户"义务（办法第十条）：
   - 发布时主动声明，并使用平台的标识功能；
   - 不得恶意删除、篡改、伪造、隐匿标识；
   - 用即梦、可灵等 API 生成的素材自带标识，不能用 VOID 或补全工具去掉（另见深度合成规定第十八条）。
   - 如果对外提供生成服务，则同时是"服务提供者"，还要履行第四、五、八、九条。

3. **真人风属于必须显著标识的场景。** 深度合成规定第十七条列明"人脸生成、人脸替换、人脸操控"等需要显著标识。

4. **视频显式标识（GB 45438 第 5.4 条）：**
   - a) 采用文字提示；
   - b) 必须同时含"人工智能"或"AI"，以及"生成"和/或"合成"；
   - c) 必须出现在**起始画面**，可在末尾和中间追加；
   - d) 位于画面的**边或角**；
   - e) 字形清晰可辨；
   - f) **字高不低于最短边的 5%**：1080×1920 即 ≥54px，建议 ASS 字号 ≥64；
   - g) 正常播放速度下**持续不少于 2 秒**。
   - 附录 C.4 示例："人工智能生成合成"放在起始画面右下角。竖屏平台右下角有按钮遮挡，建议改放左上或右上。

5. **音频显式标识（第 5.3 条，单独发布音频时适用）：** 语音提示需含上述两类要素且为正常语速（120–160 字/分钟）；或用"短长 短短"节奏（即 AI 的摩斯码），放在开头、结尾或中间。

6. **隐式标识（第 6.1 条和附录 E）：**
   - 元数据扩展字段名必须包含 "AIGC"；
   - 值为 `{"AIGC":{Label, ContentProducer, ProduceID, ReservedCode1, ContentPropagator, PropagateID, ReservedCode2}}`；
   - Label 取值：1 = 属于生成合成内容，2 = 可能是，3 = 疑似；
   - 首次写入时，ContentPropagator 填与 ContentProducer 相同的值，PropagateID 与 ProduceID 相同；
   - 字段值只能用 0x21、0x23–0x5B、0x5D–0x7E 范围内的字符以及 `\"`；
   - **文件中只能保留一份**；
   - ReservedCode1 可放哈希签名（附录 F.4）。
   - **MP4 载体**写在 `moov/udta/meta` 的 keys(AIGC)+ilst 中，即 ffmpeg `use_metadata_tags` 的写法。这一点依据 TC260-PG-20257A，来源为第三方校验库 [AigcTotal](https://github.com/StarPluckerZ/AigcTotal)，指南原文**未核**。已确认 ffmpeg 源码确实以这种结构写入（[movenc.c](https://github.com/FFmpeg/FFmpeg/blob/master/libavformat/movenc.c)）。

   - 投资 ≥100 万元的"重点"微短剧，报总局备案；

   官网 nrta.gov.cn 被代理拦截，需自行核实。

## 不确定项

- **检索不足：** WebSearch 只完成 16 次（会话额度用尽）。政府网站、comfy 文档、B站、知乎、instasd、upsampler 等站点被代理拦截，部分结论只来自搜索摘要。
- **5090 耗时都是估算：** 依据是 FlashVSR 论文中 SeedVR2-3B 在 A100 上的数据，加上第三方"5090 + 7B fp16，5 秒视频约 4 分钟"的数据点。int8 convrot 在 Blackwell 上的实际速度、0.38 优化后的提速幅度均未实测。
- **原生 int8 与 numz fp16 的画质差异没有正式对比。** Comfy-Org 的说法只是"int8 损失少量画质"。SeedVR2 原生化版本号也有出入：讨论帖称 v0.25 曾加入后回滚，PR 合并时间和 comfyui-wiki 新闻都指向 v0.28。
- **对人脸影响的判断是经验结论：** "7B 比 3B 更忠实""与底图混合能抑制塑料感"都没有严格评测。
- **新模型状态：** InfVSR 质量未验证；MotionCraft 是否开源未确认；FlashVSR 官方未确认 RTX 50 兼容性。
- **平台规格不是官方数据：** 码率、红果 AI 漫剧 24fps、单集时长、界面遮挡区和安全区坐标、LUFS 目标，均来自第三方或经验。上线前请向平台合作方要正式的交付规范。
- **TC260-PG-20257A 原文未读到：** MP4 写在 keys/ilst 这一结论来自第三方实现。平台检测工具读取哪个位置，以实际审核为准。
- **工具细节未在线复核：** 达芬奇最新版本号、字幕轨 API、OTIO 导入的起始版本、外部脚本是否只限 Studio 版；剪映是否支持导入 ProRes；抖音美好体、阿里巴巴普惠体的商用授权细节。
- **原生节点细节：** ColorTransfer、VOID 的合并日期未确认。官方 SeedVR2 视频模板默认 `color_correction=none`，而节点本身默认 `lab`，建议手动改成 `lab`。
